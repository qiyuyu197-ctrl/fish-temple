## 为什么要有自检

这个站点没有编译器兜底。改一行 `src/` 下的代码，出错的方式往往很安静：事件监听器多挂了一次、动效忘了回收、几何算错了几像素。所以补上了**两百多项自动化检查**，用真实的 Chromium 通过 CDP 驱动页面，而不是 jsdom 模拟。

一条命令跑完整套：

```bash
node tools/verify-all.mjs
```

它会自己起两个服务：开发形态的 `server.mjs`，以及部署形态的仿真器（Netlify Functions + Blobs 替身）。也可以对着真实站点跑：

```bash
node tools/verify-all.mjs --base https://yumiao.netlify.app
```

## 六个套件

| 套件 | 管什么 |
| --- | --- |
| `verify` | 路由、导航、主题、内容、相册、扫雷、工具台、代理、Markdown |
| `verify-playback` | 播放链路、后台接播、移动端、iframe 回退 |
| `verify-backdrop` | 首页 / 播放器背景：手机竖图、桌面横图、转屏重选 |
| `verify-auth` | 账号 / 权限 / 论坛 / 评论，82 项，自带模拟 IdP |
| `verify-deploy` | 部署形态：Functions、Blobs、缓存头、打包安全 lint |
| `verify-forum-ui` | 真浏览器里的登录三态、发帖、作者编辑删除、越权 403 |

另外还有 `responsive.mjs` 扫 9 个断点的横向溢出、`verify-pwa.mjs` 验图标 / Service Worker / 可安装 / 断网重开。

## 覆盖什么

- **路由**：每个 hash 渲染出的板块、标题、有无控制台报错
- **交互**：搜索 / 导入 / 播放、相册灯箱与展开、扫雷全流程、键盘与长按、联机建房
- **服务端**：网易云元数据代理、音频 Range、图片代理白名单、SSRF 防护
- **持久化**：播放列表、战绩、扫雷对局快照（含真实 `Page.reload`）
- **几何**：舞台是否按内容收缩、棋盘是否居中、封面凹槽是否压到音浪
- **动效回收**：换句翻转连发 4 次后动画数必须归零
- **权限**：伪造签名 / 过期 / `alg=none` 全部 401；未验证邮箱的站长邮箱只能算普通成员

## 四个真被它抓出来的问题

| 问题 | 表现 | 怎么发现的 |
| --- | --- | --- |
| Pixiv 图片不显示 | 代理返回的**同源路径**被“必须是 http(s)”的过滤器挡掉 | 断言“图片真的进入了 DOM” |
| 扫雷插旗无效 | 一维下标当行列传，越界后静默 return | 断言 `flags === 1` |
| 歌词动画残留 | 上一轮的收尾回调误杀了新一轮的动画 | 连发换句后断言动画数为 0 |
| 会员曲目误报在播 | 播放器条在转、歌词在走，实际没有声音 | 对比 `playing` 状态与音频探针 |

## 教训：断言不变量，别断言像素和固定延时

早期写法是“点一下 → 等 500ms → 截图比对”，这种测试会随着机器快慢随机变红。后来统一改成断言**关系**：

- 还原棋盘比的是**指纹**（每格“开 / 旗 / 雷”编码成字符串），不是格数
- “正在翻转”轮询到 `matrix3d` 那一帧，而不是 sleep 120ms
- 封面与音浪比的是“凹槽半径是否小于内半径”，不是“看起来对不对”
- 扫雷首点安全跑 **40 局**统计，而不是跑一局看运气
- 联机同步比的是“变化的格子集合”，不是“整盘重画后看起来一样”

这样测试变慢一点，但结论是确定的：它报红，就真的有东西坏了。

## 它不测什么

- **真实 Auth0 邮件链路**：要真人收信、点验证链接，自动化只覆盖令牌校验与权限矩阵。
- **AI 分轨的完整推理**：模型各 64MiB，自检只验入口、三种输出、清理滑杆，不跑模型。
- **像素级视觉回归**：没有截图比对，几何与可见性都走 DOM 断言。
- **真实手机**：移动端靠 CDP 的设备模拟与窄窗口，不替代真机。

这些边界写在测试文件顶部，免得把“没测”误当成“没问题”。
