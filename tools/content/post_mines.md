## 规则与画面分开

```
plugins/minesweeper.js   纯逻辑：布雷 / 洪水展开 / 插旗 / 和弦 / 胜负 / 统计
views/mine.js            画面：HUD、棋盘、动效、键盘、尺寸自适应
```

拆开的好处是自检能两条腿走：引擎直接跑 40 局验证规则，界面用真实 DOM 事件验证"点得到、画得出、动效挂上了"。

## 两条刻意设计的规则

**第一下必定安全**：雷在**第一次点击之后**才布置，并且避开点击格及其八邻域。所以开局第一下一定展开一片——边角至少 4 格，中间 9 格起。

**和弦**：点到已挖开的数字，如果它周围的旗数正好等于数字，就一次开完周围；旗插错了，和弦会直接踩雷（和经典规则一致）。

三档难度：初级 `9×9 / 10`、中级 `16×16 / 40`、高级 `24×16 / 75`。格子边长在 22–34px 之间按容器宽度自适应，高级在窄屏改为横向滚动，不会把版面挤爆。

## 交互都留了回执

| 操作 | 反馈 |
| --- | --- |
| 左键挖开 | 展开的格子逐格落下（14ms 级联） |
| 右键 / 长按 500ms | 插旗：格子变信号黄并弹一下 |
| 悬停数字 | 旗数够了 → 预亮将被挖开的格子；没够 → 轻轻晃一下 |
| 踩雷 | 震屏 + 全部雷按顺序翻出 + 插错的旗被划掉 |
| 通关 | 整盘按行列扫一道信号色波浪 |
| 键盘 | 方向键移动光标，空格挖开，F 插旗，R 重开 |

## 测试抓到的三个真 bug

1. **插旗完全没反应**：`toggleFlag(state, r, c)` 收的是行列，画面层把一维下标直接传了进去，被判越界后静默返回。截图看不出来（棋盘照常显示），是功能测试报的 `flags: 0`。
2. **棋盘越量越小**：舞台是 `width: fit-content`（尺寸由棋盘决定），而尺寸计算拿舞台自己当基准，形成循环——切难度时能把格子缩到最小。改成量舞台的**父容器**。
3. **长按会吞掉下一次点击**：触屏长按后如果浏览器没补 `click`，标记会一直挂着。现在 400ms 兜底清除。

## 切板块、刷新都不丢局

对局状态不能放在视图里（路由切换会换掉整个节点），所以卸载时把快照交接出去：会话内走内存变量，另外写一份进 `localStorage` 管刷新。

快照里存的不是绝对开始时间，而是「离开时已经用了几秒」，读回来再反推起点——**相当于离开即暂停**，去别的板块逛一圈不会被记上几十秒。已结算的局切回来只画结果，不会重复记一次战绩。
