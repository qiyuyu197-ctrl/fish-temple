## 三个模式，一个板块

GAME（`#/mine`）现在装了三件东西：

| 模式 | 入口 | 玩法 |
| --- | --- | --- |
| 单人扫雷 | `#/mine` | 三档难度，第一下必定安全，键盘与触屏都能玩 |
| 联机扫雷 | `#/mine?room=1` | 6 位房间号或邀请链接，几个人合作挖同一块棋盘 |
| 像素小鱼 | `#/fishrun` | 单键跳跃的跑酷，四档难度，躲水母和石头 |

原先扫雷是单独一个板块，后来把联机和小鱼收进来，导航统一成 GAME。三个模式共用同一套 HUD、棋盘样式和结算语言，切页签不会觉得换了一个站。

## 规则与画面分开

```
src/plugins/minesweeper.js   纯逻辑：布雷 / 洪水展开 / 插旗 / 和弦 / 胜负 / 统计
src/views/mine.js            画面：HUD、棋盘、动效、键盘、尺寸自适应
```

拆开的好处是自检能两条腿走：引擎直接跑 40 局验证规则，界面用真实 DOM 事件验证“点得到、画得出、动效挂上了”。

## 两条刻意设计的规则

**第一下必定安全**：雷在**第一次点击之后**才布置，并且避开点击格及其八邻域。所以开局第一下一定展开一片——边角至少 4 格，中间 9 格起。

**和弦**：点到已挖开的数字，如果它周围的旗数正好等于数字，就一次开完周围；旗插错了，和弦会直接踩雷（和经典规则一致）。

三档难度：初级 `9×9 / 10`、中级 `16×16 / 40`、高级 `24×16 / 75`。格子边长按容器宽度自适应，高级在窄屏改为横向滚动，不会把版面挤爆。

## 交互都留了回执

| 操作 | 反馈 |
| --- | --- |
| 左键挖开 | 展开的格子逐格落下（14ms 级联） |
| 右键 / 长按 500ms | 插旗：格子变信号黄并弹一下 |
| 悬停数字 | 旗数够了 → 预亮将被挖开的格子；没够 → 轻轻晃一下 |
| 踩雷 | 震屏 + 全部雷按顺序翻出 + 插错的旗被划掉 |
| 通关 | 整盘按行列扫一道信号色波浪 |
| 键盘 | 方向键移动光标，空格挖开，F 插旗，R 重开 |

## 联机：服务端权威 + 短轮询

联机房间没有用 WebSocket：棋盘状态由服务端持有，客户端每 150ms 轮询一次 `version`，变化了才拉新状态。这样做很土，但 Netlify Functions 与 VPS 都能跑，不用为一个房间常驻进程。

- 创建房间时房主选难度，其他人用 6 位房间号或邀请链接加入
- 同一块棋盘，谁揭开的都同步给全房间（合作模式）
- 视图只重画**真正变化的格子**，否则 150ms 一次的全量重绘会让棋盘发抖
- 结算页有每个人的步数 / 揭开数 / 插旗数，标一个 MVP
- 高级难度通关会播《关羽之歌》，单人局也生效

## 像素小鱼

一条单键跑酷：按空格或点屏幕开始，跑起来后再按是跳；撞到水母或石头就结束，越跑越快。四档难度，最松那档叫「杂鱼」。游戏有背景音乐，开始时播、结束时停，音量压在 0.55，不盖过判断。

## 排行榜

两个榜，规则在前后端共用同一份：

- **扫雷**按通关时间升序，只有通关的对局能上传
- **像素小鱼**按积分降序

只存前 20 名，同一昵称 10 秒内最多提交一次。分数在客户端算出来，理论上可以伪造——这是纯前端游戏的边界，站点只做范围、时间下限、频率和昵称的合理性校验；真正的防作弊得把游戏逻辑搬到服务端，现在没有做。

## 切板块、刷新都不丢局

对局状态不能放在视图里（路由切换会换掉整个节点），所以卸载时把快照交接出去：会话内走内存变量，另外写一份进 `localStorage` 管刷新。

快照里存的不是绝对开始时间，而是「离开时已经用了几秒」，读回来再反推起点——**相当于离开即暂停**，去别的板块逛一圈不会被记上几十秒。已结算的局切回来只画结果，不会重复记一次战绩。
