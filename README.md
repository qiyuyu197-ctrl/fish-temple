# FISH 鱼の灵庙 · 静态站点

一个零依赖的静态站点：**站内音乐播放 / 本地相册插画 / 文章与公告发布**，
视觉语言参考《明日方舟：终末地》官网（奶油纸底 · 墨黑文字 · 信号黄强调 · 全直角工业编辑风）。

没有构建步骤、没有 npm 依赖、没有 CDN。一个 `node server.mjs` 就能跑，也可以直接丢到任意静态托管
（但静态托管下 `/api/*` 不存在，Pixiv / 音乐台试听 / 黄历吉日之歌 都用不了 —— 想连接口一起用见「部署」一节）。

---

## 快速开始

```bash
# 1) 启动（需要 Node.js 18+）
node server.mjs

# 2) 打开浏览器
#    站点首页   http://localhost:5173
#    发布控制台 http://localhost:5173/#/admin
```

**Windows 用户可以直接双击 `start.cmd`**，效果相同（会自动切到脚本所在目录并检查 Node.js）。

> 💡 **网站打不开时**：先确认服务器还在运行 —— 运行 `node server.mjs` 的那个窗口
> 一旦被关掉，网站就连不上了。重新执行 `node server.mjs`（或双击 `start.cmd`）即可。
> 网易云搜索也依赖这个服务器，因为浏览器无法直连网易云接口。

没有 Node.js 也可以用任意静态服务器：

```bash
python -m http.server 5173
```

> ⚠️ **不要直接双击 `index.html`。** 浏览器禁止 `file://` 页面加载 ES 模块，
> 脚本会被完全拦截。此时页面会显示一段说明指引你启动本地服务器。

## 核心功能

### 1. 站内音乐（网易云集成）

- **站内搜索**：搜歌名 / 歌手 / 专辑，结果显示封面、时长、歌手。
  结果面板**紧贴在搜索条下方**（列表内部滚动，最多 460px 高），搜完不用往下翻。
  注意结果面板在官方播放器的上方，会把它整体顶下去 —— `embed-host.js` 除了观察槽位本身，
  还观察整个 `#view` 的高度变化，槽位被顶动时会重新对齐（自检里有回归用例）。
- **导入歌单**：粘贴公开歌单链接或 ID（如 `https://music.163.com/#/playlist?id=3778678`），
  也支持 App 分享出来的 **`163cn.tv` 短链**、甚至整段分享文案；一次性把整个歌单的曲目并进本站播放列表。
  支持「导入并追加」（按曲目 id 去重）与「替换列表」。详见下方「导入歌单」。
- **站内试听（默认直放）**：网易云曲目由页面自己的 `<audio>` 播放，音频流走本站服务器的
  **同源代理** `GET /api/netease/audio?id=<id>`（支持 Range/206）——服务端只转发网易云
  **对匿名访客本来就返回**的那个外链流，不登录、不碰 VIP / DRM，也不在磁盘上存任何音频。
  于是 `duration` / `currentTime` / `ended` 都是真的：一首**完整播完**才切下一首。
- **三级回退**：① 同源 `GET /api/netease/audio?id=` → ② 用**访问者自己的 IP** 直接取官方外链
  （`<audio>` 跟随 302 到 CDN，不需要 CORS）→ ③ 退回**官方外链播放器 iframe**
  （也就是下面那些限制适用的范围）。手机上的第 ③ 步需要用户点一下播放器里的 ▶，
  详见「为什么 PC 有声音、手机没声音」。
- **播放 / 暂停可用**：音乐台页面的按钮会真正控制播放；直放曲目是真实媒体元素，
  暂停 / 续播 / 拖动进度 / 音量都正常，回退的 iframe 曲目暂停会真正静音（但会从头开始）
- **切板块不断播**：离开音乐台时播放器折叠成右下角小条继续播放，回到音乐台自动展开
- ⚠️ **暂停后会从头播放——只对 iframe 回退曲目成立**：官方嵌入播放器只支持
  `type/id/auto/height` 四个参数，没有任何定位接口。详见下方「为什么暂停续播做不到」。
- **播放列表**：加入 / 移除 / 清空 / 随机 / 上一首下一首，保存在浏览器本地
- **最近播放（站内历史）**：记录**在本站真正播放过**的曲目（标题 / 艺术家 / 上次听到的位置 / 播放次数），
  每行可以「继续播放」（从上次的位置接着听）与「在网易云打开」；另有「常听」前 5 与「清空记录」（二次确认）。
  详见下方「站内播放历史」。
- **降级可用**：没有服务器时不能搜索，但可以粘贴网易云链接或歌曲 ID 直接生成播放器
- 底部常驻迷你播放条（极简「正在播放」条）：只有封面唱片 / 曲目信息 / 音浪条，切页不断。
  传输控制、进度、时间、音量、关闭按钮都已移除。
  - **点封面 = 播放 / 暂停**（不用先跳到音乐台）；折叠停靠时会先把官方播放器展开几秒，
    再开始播放 —— 既是可见反馈，也让 iframe 在被渲染的状态下加载 `auto=1`
  - **点曲目信息 = 回到音乐台**（搜索 / 播放列表 / 粘贴链接都在那一页）

#### 站内播放历史

> ⚠️ **边界（站主的明确决定，不要被后人改掉）**：这是**我们自己的**播放记录 ——
> **不接网易云账号、不存任何第三方 cookie、也不会把记录发给网易云**。
> 「在网易云打开」只是一个普通跳转链接，点不点由用户自己决定。

- **记什么**：在本站**真的出声**之后才记一条 `{ id, title, artist, seconds, at, plays }`
  （`seconds` = 上次听到的位置，给「继续播放」用；同一首反复播放只累加 `plays`，不会刷出一堆重复行）。
  没播成的不记 —— 与「不许谎报在播」同一条原则（`player:state` 报告 `playing === false` 时这里自然不记）。
- **记在哪**：只有你自己的浏览器（`localStorage`，上限 200 条，超出丢最旧）。
  登录之后额外在你**自己的账号**下存一份（服务端键 `history/<sha1(sub) 前 32 位>`，
  本地是 `data/history/`、线上是 Netlify Blobs；**只有本人能读写**），换设备也能接着听。
- **怎么合并**（客户端登录时拉一次远端）：`plays` 取大、`at` 取新、`seconds` 取较新的那条；
  回写带 4 秒去抖，切后台 / 关页面时会补一次落盘。
- **接口**：`GET /api/history`（读自己的）、`POST /api/history`（写自己的）。
  服务端严格校验：≤200 条、`id` 只允许 `[0-9A-Za-z_-]{1,40}`、文本 ≤120 字、
  `seconds ∈ [0, 86400]`、`plays ∈ [1, 100000]`；不合法 400，存储抖动 503，未登录 401。
- **实现**：`src/core/history.js`（记录 + 同步，自挂 `player:*` 事件）+
  音乐台的「最近播放」区块（`src/views/music.js`）。位置写回是节流的（默认 8 秒一次）。

#### 导入歌单

音乐台页面「导入网易云歌单」一块：粘贴歌单链接或 ID → 「导入并追加」/「替换列表」。

| 情况 | 结果 |
| --- | --- |
| 公开歌单（含排行榜：热歌榜 3778678 / 飙升榜 19723756 / 新歌榜 3779629） | ✅ 可导入 |
| **`163cn.tv` 分享短链**（App「分享 → 复制链接」得到的） | ✅ 自动展开后导入 |
| 整段分享文案（`分享歌单《X》 https://163cn.tv/xxxx （来自网易云音乐）`） | ✅ 自动抠出链接 |
| 单次上限 | 300 首（`PLAYLIST_IMPORT_LIMIT`），超出会提示「歌单共 N 首，按上限导入前 300 首」 |
| 重复导入同一个歌单 | ✅ 按曲目 id 去重，只提示「已在列表中 N 首」，不会重复堆叠 |
| 正在播放时导入 | ✅ 不打断播放（内部用 `setTracks(..., { keepIndex: true, autoplay: Player.playing })`） |
| 单曲链接（`/song?id=`） | ❌ 会明确提示「这看起来是单曲链接，不是歌单」 |
| 「我喜欢的音乐」/ 私密歌单 | ❌ 需要登录才能读，**本项目不实现登录**，会明确报错 |

实现要点（`src/plugins/netease.js` + `server.mjs`）：

- 服务端新增 `GET /api/netease/playlist?id=<id>&limit=<n>`，转发 `api/v6/playlist/detail`，
  只取**元数据**（歌名单 / 封面 / 曲目 id 列表），不涉及音频流，也不需要 cookie 或登录。
- 大歌单的 `tracks` 字段只给前几首，**完整顺序在 `trackIds` 里**：接口返回的 `tracks` 够用就直接用，
  不够的部分按 50 首一批调 `/api/netease/songs` 补齐（单批失败不整体失败，能拿到多少算多少）。
- 两个接口的字段名不一样（`/songs` 用 `artists`/`album`/`duration`，`v6/playlist/detail` 用 `ar`/`al`/`dt`），
  服务端的 `shapeSong()` 两套都认 —— 否则导入进来会是一堆没歌手没封面的空壳。
- **短链必须在服务端展开**：`163cn.tv/xxxx` 会 302 两次
  （`→ music.163.com/m/playlist?... → music.163.com/playlist?id=...`），
  浏览器读不到跨域 302 的 `Location`（CORS 不允许），所以加了
  `GET /api/netease/resolve?url=<encoded>` 由 Node 跟随跳转。
  这是「服务端替你请求一个 URL」，所以做了 SSRF 防护：**只允许网易云域名，且每一跳都校验**
  （`example.com` 与 `127.0.0.1` 都会被 400 拒绝，自检里有回归用例）。
- 普通歌单链接不会去走短链解析（少一次网络请求）：`expandLink()` 先试直接解析，只有识别为短链才展开。
- **专辑链接也走同一条路**。App 分享出来的专辑短链（`https://163cn.tv/xxxx`）会跳成
  `y.music.163.com/m/album?...&id=…`，所以 `parseAlbumId()` 三种形态都认
  （`/album?id=`、`#/album?id=`、`/m/album?…&id=`），服务端用
  `GET /api/netease/album?id=…` 取整张专辑（**用 v1 接口**：老的 `/api/album/<id>`
  现在常回 `-462`「绑定手机」风控页，v1 匿名态可以直接拿到专辑信息与完整曲目）。
  界面上粘什么都能用：`classifyLink()` 先展开再判类型，歌单 → `importPlaylist`，专辑 → `importAlbum`。
- 导入的仍然只是曲目元数据；试听默认走站内直放（同源代理匿名外链流），失败才回退官方外链播放器（版权与登录由网易云处理）。

#### 「不断播」是怎么做到的

> 这一节只讲 **iframe 回退路径**的不断播；直放曲目走页面自己的 `<audio>`，
> 不涉及跨域 iframe 被重建的问题。

官方播放器是个 iframe。最初它挂在音乐台的视图里，切板块时视图重建会连 iframe
一起销毁，播放随即中断。现在的做法（`src/ui/embed-host.js`）：

1. iframe **只创建一次**，永久挂在 `<body>` 下的 `#embedHost`（在 `#view` 之外）
2. 音乐台页面提供一个占位槽 `[data-embed-slot]`
3. 切板块时只改 `#embedHost` 的 `data-dock` 属性：
   - `inline` — 用 `position: fixed` + CSS 变量精确对齐到槽位（视口坐标，随滚动/缩放实时重算）
   - `docked` — 折叠成右下角小条，鼠标悬停或聚焦才展开
4. **元素本身从不移动、不重建** —— 移动 DOM 节点会让 iframe 重新加载，那正是断播的根因
5. **折叠态下换歌时先"展开一下"**（`expandBriefly`，见下）：折叠时 iframe 的祖先带
   `display: none`，浏览器对「不可见的跨域 iframe 自动播放」判定更严，下一首会起不来 ——
   自动接播正好会在折叠态触发（用户在别的板块 / 后台听歌），所以换歌前先让它被渲染出来，
   2 秒后自动收回小条，音频不受影响。

自检里有专门的回归用例（`持续性：切到文章板块后 iframe 未被重建`），
同时校验 `sameElement` / `sameContentWindow` / `sameSrc`，防止以后被改回去。

### 放完就接上是怎么做到的（自动接播 · iframe 回退路径）

> **适用范围**：这一节现在只描述 **iframe 回退路径** —— 直放拿不到流、被标成 `embedOnly` 的曲目
> （会员 / 版权受限）。走直放的曲目有真正的 `ended`，不靠估算：一首完整播完就切下一首，
> 后台 / 息屏也照常（见下一节「为什么改成站内直放」）。
> 代码里那套估算时钟（`EMBED_BELL_S` + 静音 WAV 秒表 + `_scheduleAdvance`）仍留在
> `src/core/player.js`，只是现在**只对 `embedOnly` 曲目生效**。

「一首放完立刻接下一首」是听歌的常态，所以这个功能**默认开着**。
难处只有一个：官方 iframe 不给播放结束回调，只能按时长估算。而这里有个**大坑**：

> **官方外链播放器把单曲嵌入当成长度 1 的列表循环播放。**
>
> 它自己的 JS（`pt_outchain_player_*.js`）里，切歌函数是这样的：
>
> ```js
> Id8C = function (index) {
>   index = parseInt(index) || 0;
>   if (index > this.gq8i.length - 1) index = 0;      // ← 越过末尾就回到第 0 首
>   else if (index < 0) index = this.gq8i.length - 1;
>   var item = this.gq8i[index];
>   if (item.status < 0 || (item.fee > 0 && item.fee != 8)) return;   // VIP：直接不播
>   this.dN0u.ez4u('', item.id);
> };
> ```
>
> 我们只传一首歌，列表长度就是 1；它在 `ended`（state 4）时推进索引 → `1 > 0` →
> **回到第 0 首，同一首重头再放一遍**。所以站内只要"等到估计播完了"才切歌，
> 用户就会先听到**上一首的开头重播几秒**，然后才是下一首。
> （顺带印证了 VIP 判定：播放器自己对 `fee > 0 且 fee != 8` 的曲目直接 `return`，不出声。）

所以"提前切"不是调参爱好，而是**必须**：

| 关键点 | 做法 |
| --- | --- |
| iframe 创建 ≠ 音频起播 | 锚点挪到 iframe `load`，再补 **350ms** 缓冲补偿（早先给 1.5 秒，那是**偏晚**的方向，正好落进上面那个循环里） |
| **元数据时长 ≠ 音频时长**（试听片段、现场版、上传错误） | 服务端 `GET /api/netease/playable?detail=1` 从**音频本身**量秒数：CBR 按码率、VBR 按 Xing 帧数，量出来优先用 |
| 必须在音频结束**之前**切走 | 触发点 = `时长 − 0.8s`（`EMBED_BELL_S`）。代价是可能吃掉收尾半秒的淡出，换回来"下一首立刻接上、不会先放错歌" |
| 关掉自动接播之后呢？ | **不是不管**：改布防成 `时长 + 0.3s` 时**停住**，否则官方播放器的单曲循环会让它无限重播 |
| **窗口放后台就失灵** | 后台标签页的定时器会被节流（实测隐藏 6 分 20 秒里 `setInterval(500)` 只跑了 121 次、单次最大间隔 **60 秒**）→ 切歌要么晚一分钟、要么拖到切回前台才执行。所以计时换成**静音媒体秒表**，见下 |
| 用户拖了进度 / 在官方播放器里按了暂停 | **放弃这一首的估算**（位置无从推断）并提示一句；换歌后自动恢复 |

**为什么计时要用"静音媒体秒表"**（`CLOCK_RATE` / `_armClock` / `_resyncClock`）：

媒体事件不由定时器驱动，而是跟着媒体管线走，**后台标签页里不会被节流**。于是：

- 生成一段**静音** WAV（8kHz / 8bit / 单声道 = 8KB 每秒，20 分钟也才 9.6MB，只生成一次后复用），
  用隐藏的 `<audio muted>` 播放它，拿它的 `timeupdate` / `ended` 当秒表 —— 与真正的音频同一条时钟；
- 实测（隐藏 6 分 20 秒）：普通计时器被节流到 **60 秒一次**，而秒表的 `currentTime`
  始终按 10 秒 / 10 秒推进；两次切歌都**按时**发生 —— 第二次还是在计时器已经 60 秒没跑的情况下；
- 秒表本身也可能被省电策略挂起（不发声的媒体会被暂停），所以兜底计时器每次跑起来都会
  **对一次表**（`_resyncClock`：暂停了就接着放、跑偏了就 seek 回去），回到前台再对一次（`_checkAdvanceNow`）；
- 静音是硬要求：它唯一的职责是计时，绝不能发出声音（`muted` + `aria-hidden` + 移出视口）。

还有一个容易误报的地方：判断"用户动过官方控制条"用的是 iframe 的 `focus` 事件，
而**窗口切到后台、或被别的窗口盖住时 iframe 也可能收到 focus** —— 那时位置根本没变，
误判会变成"后台放着放着就不切歌了"。所以现在额外要求**窗口有焦点且页面可见**才算数。

最后一条靠"间接信号"实现：用户点进 iframe 时，顶层文档失焦、`document.activeElement`
变成那个 iframe —— 跨域读不到里面的进度，但**能知道它被动过**。这时把正在听的歌切走，
比少切一次严重得多，所以宁可停下来让用户点 ⏭。
> 想彻底不要自动切：音乐台播放列表标题行的 **「播完自动下一首」** 关掉即可（状态存在 `Settings`）。
> 本地音频不受影响 —— 它有真正的 `ended` 事件，一直是最可靠的。

### 为什么改成站内直放：后台 / 息屏也要能自动切歌

「放完一首不会自动切下一首」的根因不是参数没调好，而是**旧方案里根本没有「放完」这件事**：
官方 iframe 读不到 `currentTime`、也没有 `ended` 回调，站内只能用「时长估算 + 静音秒表」猜它
什么时候结束。而估算依赖定时器与媒体事件，后台标签 / 最小化窗口 / 手机息屏时会被浏览器节流或
冻结，于是切歌要么晚一分钟，要么拖到切回前台才执行。

现在的默认路径（`PLAYER.directAudio: true`）把这件事交给**媒体管线**：

| 环节 | 做法 |
| --- | --- |
| 音频从哪来 | 页面自己的 `<audio>` 播 `GET /api/netease/audio?id=<id>` —— 本站服务器**同源代理**的匿名外链流（支持 Range/206，`Cache-Control: private, max-age=86400`）。服务端 `resolveNeteaseAudio()` 按顺序试两个入口：① `music.163.com/song/media/outer/url?id=<id>.mp3`（302 → CDN）② `/api/song/enhance/player/url?ids=[<id>]&br=128000`；URL 过网易云 CDN 白名单并升级 https，解析结果缓存 **15 分钟**；音频只在内存里流转，**不落盘** |
| 为什么这样就能自动切 | 它是真正的媒体元素：`duration` / `currentTime` / `ended` 都是真的。一首歌**完整播完**，下一首由媒体管线驱动 —— 后台标签、最小化、手机息屏都照常 |
| 移动端后台播放 | 注册 **Media Session API**（`_bindMediaSession`）：锁屏 / 通知栏 / 耳机线控的播放暂停与上一首下一首、以及进度状态 |
| 切歌接缝 | 下一首**预加载**（`_primeNext`，`PLAYER.preloadLead = 45`：结束前 45 秒开始准备），切换几乎无缝 |
| 自愈 | `_bindLifecycle` 在 `visibilitychange` / `pageshow` / `focus` / `resume` 时重查结束状态，并把浏览器自己暂停掉的播放恢复回来（仅当用户意图是「在放」） |
| 直放失败怎么办 | 三级回退：① 同源 `/api/netease/audio?id=`（服务端 IP 解析）→ ② **访问者自己的 IP** 直接取官方外链（`rawAudioUrl`；`<audio>` 跟随 302 到 CDN 不需要 CORS）→ ③ 退回官方 iframe 播放器（也就是上一节那套旧方案）。② 这一步**不看服务端的 404 结论**，因为那个结论只描述服务端的 IP |

Provider 层面是两个 id：`netease-audio`（直放，`embed: false`，在 `src/plugins/netease.js` 里注册为
`neteaseAudioProvider`）与 `netease`（iframe）。曲目数据里的 `provider` 仍写 `netease`（持久化与
界面用它），运行时由 `Player.resolveProviderId()` 解析。

> 顺带修掉一个 bug：`Player.play()` 以前在 `track.src` 为空时会直接提示「尚未配置音频文件」——
> 而直放的网易云曲目恰恰没有 `src`（URL 由 provider 给），于是直放永远起不来。

> 自检：`node tools/verify-playback.mjs [baseUrl]`（无头 Edge/Chrome + CDP）会种入 3 首匿名可播的
> 曲目，断言 provider 是 `netease-audio`、有真实时长、进度在走、Media Session 元数据对得上，
> 并让一首**播到结束自动跳下一首**（**前台与 `document.hidden === true` 各一遍**），
> 再在 360 / 390 / 430px 三个手机宽度 + 触摸模拟下检查移动适配层（无横向滚动、触控尺寸、
> 音浪条保留、宽表可滚动、manifest / iOS 全屏声明、顶栏图标不被裁切、黄历面板不溢出），
> 截图存进 `.shots/`；失败退出码 1。实测 **43/43 PASS**。

### 为什么「暂停续播」做不到（重要 · 仅 iframe 回退）

> **适用范围**：这一节只针对 **iframe 回退路径**。直放曲目走真实 `<audio>`，
> 暂停 / 续播 / 拖动进度 / 音量**都正常** —— 只有回退到 iframe 的曲目才受下面这些限制。

网易云官方外链播放器 `music.163.com/outchain/player` **只支持四个参数**：

```
type=2        单曲
id=<歌曲 ID>
auto=0|1      0 不自动播放，1 自动播放
height=106    高度
```

没有 `startTime`、没有 seek、没有音量。而且它是跨域 iframe——
`contentWindow` 被同源策略拦死、不接受 `postMessage`、也不暴露 `currentTime`
（这三条均实测验证过）。

于是形成一个死结：

- 要**暂停** → 必须把 iframe 重新加载成 `auto=0`（唯一能让它静音的开关）
- 重新加载 → 播放位置必然回到 `0:00`
- 想**恢复到原位置** → 官方没有提供任何定位参数

**结论：在 iframe 回退路径（官方嵌入方案）下，「暂停后续播」在技术上无法实现。**

### VIP 曲目为什么没声音，以及现在怎么处理

> **适用范围**：VIP / 版权受限曲目**两条路径都放不出声**：直放时服务器拿不到匿名流（`404`），
> 这首会被标成 `embedOnly` 回退到 iframe —— 也就是说下面这些只发生在**回退曲目**上，
> 能直放的曲目不受影响。

现象：播《逆さまの蝶》这类 **VIP / 付费专辑**曲目时，官方播放器条在转、站内歌词也跟着走，
但一点声音都没有。原因有两个叠加：

1. **官方外链播放器不对匿名访问者放 VIP 曲目的音频**。实测：
   `GET /song/media/outer/url?id=<id>.mp3`（不跟随跳转）
   - 免费曲目 → `302` 到音频路径
   - VIP 曲目（`fee=1`）→ `302` 到 `/404`
2. 站内的歌词时钟是**自建估算时钟**（官方 iframe 读不到进度），它只知道"这首歌在播"，
   不知道播放器其实没出声 —— 于是就成了「歌词在动却没声音」。

**能不能修成"能听"？** 不能。站内现在确实会转发音频流，但只转发**网易云对匿名访客本来就返回**
的那个外链流（见「为什么改成站内直放」）；VIP 音频只能凭登录态从 `/api/song/enhance/player/url`
取到，要让它出声就得由服务端带着用户 cookie 取音频再转发 —— 那是本项目一直拒绝做的事
（不登录、不逆向 weapi/eapi，见上面的能力边界表）。
所以这里做的是**把话说清楚 + 给出能听的替代**：

| 做的事 | 位置 |
| --- | --- |
| 服务端匿名探测能否播放（结果缓存 30 分钟） | `GET /api/netease/playable?id=…` |
| 搜索结果里会员曲目带 `VIP` 标 | 音乐台搜索结果 / 播放列表行 |
| 「只看能播的」一键过滤掉会员曲目 | 搜索结果标题行 |
| 播到会员曲目时，在「正在播放」里弹出说明块 + **同名可播放版本**（一键切换） | `#neSilent` |
| 歌词块标题变成 `LYRICS · <歌名> · 可能无声`（红色、整块压暗） | 板块标题栏 / 首页 |

> 探测拿到的结论是**匿名态**的：如果你在浏览器里登录了网易云会员，外链播放器通常就能正常出声，
> 所以站内只是"提示 + 给替代"，不会阻止播放。**真的登录了会员的人可以点
> 「我登录了会员，能听到声音」把提示收起来**（存在 `localStorage['ft.terminal.vipLoggedIn']`，
> 之后只剩一行可撤销的说明，切板块也记得）。
>
> 另外 `fee` 只能当提示、不能当结论：`fee=8`（低音质免费）其实**能放**，
> 实测 `2683804669` 探测结果是 `true` —— 所以最终判定一律以服务端探测为准。
>
> 还有一种情况探测不出来：**个别曲目网易云只给试听片段**（确实有音频，但不是完整版）。
> 服务端能判断"这个 id 匿名态拿不拿得到音频"，判断不了"拿到的是不是完整版"。
> 遇到「能放、但一小会儿就停」的曲子，用提示块里的同名可播放版本换一首即可。

### 为什么 PC 有声音、手机没声音

现象：网易云《No Why（游戏《少女前线》最终章「零态潮汐」主题歌）》（id `2757934332`）
在 PC 上听着有声音，同一首在手机上一声不响。查下来是两个原因叠加：

1. **服务端原先只会用一个入口解析音频**。原来只走 `GET /song/media/outer/url?id=X.mp3`，
   而这条入口对 `fee=8`（低音质免费 / 高音质付费）的曲目答 **`302 → /404`** ——
   于是这首被判成"匿名态没有音频"，客户端回退到网易云官方 iframe 播放器。
   **PC 上那个 iframe 通常会自动起播，所以在 PC 听起来一切正常；而手机浏览器
   （iOS / Android）拒绝自动起播跨域 iframe，必须用户自己去点 iframe 里的 ▶，
   不点就是静音。** 这就是「PC 有、手机没有」的来源。
   现在 `resolveNeteaseAudio(id)` 按顺序试**两个入口**（各带独立超时）：
   ① 官方外链 `outer/url`（长期存在的、被允许的匿名通路）；
   ② `/api/song/enhance/player/url?ids=[X]&br=128000`。
   `/api/netease/playable` 也复用**同一个解析器** —— 否则"能不能播"的判定与实际播放会分叉。
2. **只请求 128000（免费档），绝不请求更高码率** —— 原因见服务器 API 一节的 ⚠️ 规则。

> 同一个 id，本地（国内家宽 IP）能解析、线上（Netlify Functions 跑在 AWS）解析不了，
> 是网易云**按 IP 区别对待**，不是 bug —— 所以下面这条回退链里专门加了
> 「用访问者自己的 IP 再试一次」。

客户端的三级回退链（顺序即优先级）：

| 顺序 | 走哪条路 | 说明 |
| --- | --- | --- |
| ① | 同源 `GET /api/netease/audio?id=<id>` | 服务端 IP 解析 + 同源代理；拿到就同时拥有真 `duration` / `ended`（默认路径）|
| ② | **访问者自己的 IP** 直接取官方外链 | `rawAudioUrl`，`<audio>` 跟随 302 到 CDN **不需要 CORS**。救的正是"服务端 IP 被拒、访问者自己的 IP 可以"的曲目（线上实测：服务端回 `404` 的一首，在浏览器里能正常播放）。这一步**不再咨询服务端的 404 结论** —— 那个结论只描述服务端的 IP |
| ③ | 网易云官方 iframe 播放器 | 前两级都拿不到时。窄屏 / 触摸屏会把它停靠到屏幕底部并保持展开（见下），手机上仍需点一下 ▶ |

**「手机上必须点一下」这个坑现在有专门引导**（`embed:needsTap`）：

- **窄屏 / 触摸屏**：把官方播放器 `dock('docked')` 到底部并 `pinExpanded(true)` 保持展开，
  让 ▶ 直接出现在眼前（`noteRoute` 在 pinned 状态下不会再把它拉回内联槽位）；
- **宽屏**：只把它滚动到可见（`bringIntoView`，布局变化后会复核）；
- **刻意不改**用户保存的紧凑 / 完整播放器偏好（`setCrop`）—— ▶ 本来就在紧凑控制条里；
- 触发点必须**两条路都发**：`<audio>` 的 error 回退，**以及** `neteaseProvider.play()`
  （被判"不可播"的曲目会直接进 iframe，根本不经过 `onError` —— 这是用线上几何诊断抓到的真实遗漏）；
- 音乐台里的提示文案也改成可操作的：明确说"手机浏览器不会自动起播官方播放器，请点它的 ▶"。

还有一个**只在线上出现的死状态**也一并修了：界面显示"正在播放"、`readyState === 0`、
既没声音也没有任何提示。原因是**换 `src` 会触发一次 abort（`error.code === 1`），
把紧随其后的 `404` 掩盖掉**，于是整条回退链被跳过。现在 `src/core/player.js` 里有
**停顿看门狗**（`_armStallWatch` / `_onError({ force: true })`）：只要元素带着错误、
`networkState === 3`（无可用源），或者声称在播却**连续 10 秒一个字节都没收到**，
就重新判定并强制执行失败处理。

### 为什么不做「登录网易云账号」（含播放记录同步）

有人会问：能不能登录网易云账号，让播放次数计入自己的账号，顺便让 VIP 会员听到会员曲目？
**技术上做得到，但这个项目不做**，理由如下（都尽量给了可核实的依据）：

1. **第三方登录会被风控，风险落在用户账号上**。这不是猜测：几个最大的第三方网易云客户端
   都发过公告 —— YesPlayMusic 的
   [「不要登录！任何使用开源网易云 api 的软件，否则会被认定账号异常冻结三天」](https://github.com/qier222/YesPlayMusic/issues/2311)、
   SPlayer 的[「近期请勿在第三方客户端中登录账号，否则将会导致封号」](https://github.com/SPlayer-Dev/SPlayer/issues/270)。
   让访问者把账号密码（或扫码会话）交给本站，等于把他们送进这个风险里。
2. **要做到"能放"，就必须搬运音频流**。VIP 音频只能凭登录态从
   `/api/song/enhance/player/url` 拿到，而那正是官方播放器自己在调的接口（实测外链播放器
   的 JS 里就是它）。要在我们自己的页面里播，就得由服务端带着用户的 cookie 取音频再转发 ——
   这正是本项目一直拒绝做的事（见上面的能力边界表）。
3. **接口是未公开的加密接口**（weapi/eapi），随版本变动，维护成本高且不稳定。

**那"会员能听 VIP"和"播放记录同步"到底怎么办？** 有一条不用写任何登录代码的路子：

- 外链播放器 `music.163.com/outchain/player` **本身就是网易云的页面**，
  它调的是同源的 `/api/song/enhance/player/url`，会**带上浏览器自己的 cookie**。
  所以只要你在**浏览器里登录一次 music.163.com**，站内这个 iframe 通常就能放 VIP 曲目，
  播放次数也由官方播放器自己上报 —— 不需要本站碰任何凭据。
  （这一条我无法用 VIP 账号实测，但接口层面的依据是上面第 2 点里那段 JS：它调的确实是
  需要登录态的 enhance 接口。试一下就知道，站内还会给你一个「我登录了会员」的开关。）
- 想要**真正属于本站的播放记录统计**，两条正道：本地统计（最近播放已经在存了，可以加"播放次数
  排行"，纯 `localStorage`，零依赖），或者 [Last.fm 的官方 scrobble 接口](https://www.last.fm/api/show/track.scrobble)
  —— 那是为第三方应用设计的公开 API，有正经的授权流程，不涉及任何账号风险。

> 你在别处见到的"能暂停续播"的网易云播放器，用的都是逆向接口或第三方
> 曲库代理（Meting / APlayer 等）——依赖别人维护的私有服务，随时失效，
> 且明确违反网易云服务条款。本项目不提供这类实现。

### 如果你需要真正的暂停 / 续播 / 拖动进度

把音频文件放进 `assets/audio/`，用**本地来源**——它走 `<audio>` 元素，
是真正可控的播放器：暂停续播、拖动进度、音量、真频谱全部可用。
（网易云曲目现在默认也走 `<audio>`，暂停续播 / 拖动进度 / 音量同样可用，只有回退到 iframe 的曲目不行。）

```js
// src/config/site.config.js
export const PLAYLIST = [
  { id: 'tr-01', title: '曲名', artist: '作者', src: 'assets/audio/your-track.mp3', cover: '', tags: [] },
];
```

两种来源可以共存：本地音频走 `<audio>`；网易云曲目默认也走 `<audio>`（同源直放），
只有回退到 iframe 的曲目由官方嵌入播放器出声。界面会用 `本地` / `NETEASE` 标签区分。

#### 官方播放器怎么「融入」站内

官方嵌入播放器是一张**白底圆角卡片**（跨域 iframe，内部样式完全碰不到），
直接塞进站内非常刺眼。改造思路是「不动 iframe、只改我们自己这一侧」：

| 做法 | 说明 |
| --- | --- |
| **默认只留一条控制带** | 裁掉封面与标题，只保留进度条 / 时间 / 播放键。封面和标题站内的 NOW PLAYING 卡片已经显示过，留着纯属重复。裁剪用 `clip-path: inset(58px 0 0 108px)`，同时把 iframe **加宽 108px 并左移**，让保留下来的内容正好从面板左边缘开始 —— 否则左边会空出一条黑带，看着像图标没加载出来 |
| **槽位按站内面板语言重做** | 硬边零圆角、等宽大写标签、状态点、HUD 角标；原来的虚线框改成和别的面板一样 |
| **浅色主题把白底 multiply 掉** | `mix-blend-mode: multiply`：白 × 纸色 = 纸色，卡片自然"消失"，红标和文字照旧 |
| **深色主题反色** | `filter: invert(0.92) hue-rotate(180deg)`：白底变墨底、文字变亮。因为封面已经裁掉，不会把插画反成负片。`invert` 用 0.92 而不是 1，白底落在 `#141414`，正好接上 `--bg-alt` |
| **一键切回官方完整形态** | 槽位标题栏上的「完整播放器 / 仅控制条」，选择记在 `localStorage`（键 `ft-embed-crop`）。需要网易云自己的播放列表时就切过去 |
| **不重复放关闭键** | 内嵌形态下隐藏宿主自带的 ✕，改用槽位里的「✕ 停止」；右下角折叠形态仍保留 ✕ |

> 裁剪坐标是在 **647px 宽的槽位**下量出来的（封面 x<105、标题 y<58、进度条 y≈62、控制排 y≈85）。
> 槽位窄于 560px 时官方播放器内部会重排，CSS 里会用媒体查询自动退回完整播放器，避免裁错。
> 自检里有 5 条用例卡着这套改造（默认形态 / 切换与记忆 / 配色滤镜 / 不重复关闭键 / 停止回到待机）。

#### 板块标题栏里的歌词（跟唱）

播放网易云曲目时，**每个板块标题栏右侧那块空白**会显示当前行 + 下一行（`viewhead` 生成的
`.lyricbox`），点开是完整歌词浮层：当前行高亮、自动居中、可 `−0.5s / +0.5s` 校准。
歌词文本由 `server.mjs` 的 `/api/netease/lyric` 代理获取（只取文本，不碰音频流）。

> 时间轴这一块是为 **iframe 回退路径**写的：跨域 iframe 读不到进度，只能自建时钟。

时间轴是这套方案的**关键取舍**：

| 事实 | 结果 |
| --- | --- |
| 官方嵌入播放器是跨域 iframe：读不到 `currentTime`，也没有任何进度事件 | 没法用「真实播放位置」驱动歌词 |
| 但它只有一个「从头播」的行为：暂停 = 重建 `auto=0`，继续 = 重建 `auto=1`，两者都回到 `0:00` | 于是**自己起一个时钟**：什么时候把 `auto=1` 的播放器推进去，就从那一刻计时；暂停停表、继续归零 |

因为官方播放器每次都从头开始，这个自建时钟和真实播放位置是一致的；
唯一误差是 iframe 加载耗时，用 `OFFSET_MS = 600`（`src/plugins/lyrics.js`）做常数补偿。
**代价**：如果你在官方播放器里手动拖了进度条，歌词就会偏 —— 浮层里的 ±0.5s 就是给这种情况兜底的。

要点：

- 没在听歌时整块 `[hidden]`，**不占位**，对不听歌的人零影响
- **换句有翻转动效**：旧句往上翻出去（`rotateX(62deg)` + 上移 + 淡出，170ms），
  换完文案新句再从下往上转进来（260ms），像机械翻牌；父级 `perspective: 620px` 给立体感。
  用 Web Animations API 而不是 CSS 类名（换句是事件驱动的，用类名得自己管「动画结束」的状态，
  快速连换时容易卡住）；动画结束的状态和元素默认状态一致，所以立刻 `cancel()` 掉，
  一首歌几十次换句也不会攒下一堆挂着的动画 —— 自检里有一条连续快进 4 次的用例卡这个。
  `prefers-reduced-motion` 或站内「减少动效」打开时直接换文案，不做动画。
- 开头 3 秒内带时间戳的「作词 / 作曲 / 编曲 / 制作人…」会被过滤（它们是制作信息，不是歌词）
- **首页也有**，走的是另一套排版：大标题和歌词并排成两列（`hero__stage`），歌词正好落在
  标题右边那块空白里；**窄于 1080px 时自动并成一列**，歌词落到标题下方（不压标题）
- 首页歌词**下面还有一条波浪形音浪**（`ui/wave-row.js`）：**和底栏那条是同一套东西** ——
  同样的 `.mp-wave` 外观、同样 40 根条、同样的幅度来源（`miniaudio.js` 的
  `pumpVisualizer` + `waveLevels`），所以两处波动完全一致；左边配一个会转的小封面
  （46px 唱片，复用底栏的 `mpSpin`）。没有曲目时整块收起。

  > 曾经做过一版**圆环**（封面在圆心 + 径向条），最后放弃了：为了让封面塞进圆心，
  > 得反复调「封面 + 凹槽」与音浪内半径的关系，一动就顶到环根上（第一版就是这样，
  > 看起来像封面跑到环外）。波浪条没有这种几何耦合，也和站里其它地方更统一。

  > 另外记一个 CSS 坑：`.wave-row__wave` 要覆盖 `.mp-wave` 的固定宽度和
  > `margin-left: auto`，而 **base.css 在 components.css 之前加载** —— 同优先级下靠顺序
  > 决定胜出，所以这组覆盖必须写在 components.css 里 `.mp-wave` 之后，写在 base.css 里
  > 会静默失效（第一版就踩了，波浪条宽度只有 250px 还贴在最右边）。

- 纯音乐或没歌词 → 标题栏显示「纯音乐 · 没有歌词」；本地音频 → 「本地音频 · 没有歌词来源」
- 自检里有 10 条用例：LRC 取回与过滤、标题栏内容、时钟在走、**切板块依然显示**、
  **首页大标题右侧不压标题**、**波浪条（位置 / 与底栏同款 / 真的在动）**、
  完整浮层、LRC 解析、**换句动效与动画回收**

#### 版面结构：一个输入框 + 三块面板

音乐台从上到下就三块面板，功能一眼能找到：

| 面板 | 内容 |

> `NOW` 在「正在播放」里已经有了 —— 都属于噪音。自检里有 4 条用例卡这套结构

### 2. 黄历小组件（顶栏 · `#almanacBtn`）

顶栏搜索图标**左边**多了一个小按钮（`#almanacBtn`，就是 `.iconbtn` 那一套：桌面 34px / 触屏 44px），

1px 硬边、零圆角、等宽小标签，信号黄只用来强调，不加阴影与渐变；
只有吉日之歌那一条有 700ms 淡入。

### 3. 相册（本地照片）+ 随机插画

因为 Pixiv 官方 API 需要 OAuth 与服务端代理（本项目不接），**随机插画默认用自己的照片**：
把手机相册里的图片导入站点，随机抽取与网格浏览都走本地文件，完全离线。

#### 从手机导入相册（两步）

```powershell
# 1) 手机用数据线连上、信任本机、保持解锁，然后随机抽取 N 张原图到 staging
powershell -ExecutionPolicy Bypass -File tools\album-pull.ps1 -Count 180

# 2) 压缩成网页素材（长边 1600px / JPEG q82）+ 生成缩略图 + 写清单
python tools\album-build.py
```

产物：

| 路径 | 内容 |
| --- | --- |
| `assets/img/album/album-001.jpg …` | 正图（灯箱 / 舞台用），长边 ≤ 1600 |
| `assets/img/album/thumbs/album-001.jpg …` | 缩略图（网格用），长边 ≤ 480 |
| `data/album.json` | 相册清单：url / thumb / 标题 / 尺寸 / 字节数 |

这次导入的规模：**分两批从 66 个相册分组、4883 张里随机抽了 780 张**（先 180、再补 600），
压缩后 **770 张入库，共 177MB**（正图均 206KB、缩略图均 29KB）。

实测细节（都是踩过的坑）：

- iPhone 通过 USB 是 MTP 便携设备，PowerShell 的普通文件 API 读不到，只能用
  `Shell.Application` 逐个枚举 / `CopyHere` 拷贝；枚举很慢，脚本会把清单缓存到
  `candidates.json`，重跑秒过；**已经拷过的会自动跳过**，所以可以分多次补量
  （`-Count 600` 再跑一次就是纯增量）。
- MTP 给的文件名经常没有扩展名，或扩展名与实际内容不符（实测有内容是 JPEG 却叫 `.PNG`
  的），所以 `album-build.py` 一律**读文件头**判断格式。
- iPhone 原图多是 HEIC；本次 `CopyHere` 拿到的大多已是 JPEG，仍有 4 张 HEIC 无法解码被跳过
  （Pillow 默认不带 HEIF 解码器）。想全部导入可在 设置 → 相机 → 格式 里改成「兼容性最佳」。
- 生成的 JPEG **会剥掉全部 EXIF**（含 GPS、设备型号、拍摄时间），只保留像素。
- staging 目录（默认 `D:\ft-album-staging`，老位置 `%USERPROFILE%\Downloads\ft-album-staging` 仍兼容）留着原图便于换参数重跑，
  不需要时可以直接删。

#### 随机插画引擎

| 数据源 | 类型 | 说明 |
| --- | --- | --- |
| **相册**（默认第一个） | 本地 | `data/album.json`，手机照片，秒出图 |
| LOCAL 本地画廊 | 本地 | `data/gallery.json`，手工维护 |
| NEKOS.BEST / WAIFU.PICS | 远端 | 公开 API，需要网络 |
| **PIXIV 随机** | 远端 | 经 `server.mjs` 代理取随机作品，图片走 `pixiv.re` 镜像（见下节） |
| PIXIV 深链 | 跳转 | 兜底：只生成搜索 / 榜单链接，不返回图片 |

引擎的健壮性与随机性：

- 多数据源**依次尝试**，第一个能出图的就赢（相册优先，所以断网也有图）
- 每张图先做预加载校验（超时按数据源可配：本地 4 秒、普通远端 6 秒），坏图自动跳过；
  全部失败回退历史。**Pixiv 例外**：它不做阻塞探测（图已走本地缓存，直接交给 `<img>` 边下边显示）
- **洗牌袋**：整份清单打乱后顺序发牌，取完一轮再重新洗牌 —— 同一轮内不重复，也不会
  像早期实现那样「只想抽到前 12 张」（清单变大后那个 bug 会让随机看起来像坏了）
- **不连着抽到同一张**：最近 5 张会从候选里排除；池子快用完时自动重新拉一批
- 历史最多 40 张，支持上一张 / 下一张回溯、删除、灯箱全屏、收藏到本地画廊

#### Pixiv 图片为什么显示不出来，以及现在怎么解决的

**结论：直连不行，但已经解决 —— 站内能显示 Pixiv 随机图了。**

三重障碍（都是实测结果，不是猜的）：

1. **DNS 被污染**：本机解析 `www.pixiv.net` → `31.13.94.41`（这是 FaceBook 的 IP），
   `i.pximg.net` → `128.121.243.106`（已知投毒地址）。TCP 根本连不上，`fetch` 全部超时。
2. **i.pximg.net 有防盗链**：`Referer` 不是 pixiv 就返回 403；而加
   `referrerpolicy="no-referrer"` 同样会被拦（它要求**有**正确的 Referer）。
3. **官方 API 要 OAuth**：`client_id`/`secret` + PKCE，本项目不接任何第三方账号体系。

现在的链路：

```
浏览器  →  GET /api/pixiv/random?num=8             ← 本站 server.mjs（同源，无 CORS 问题）
           →  https://api.lolicon.app/setu/v2      ← 第三方随机作品接口（不返回 CORS 头，必须服务端代理）
           ←  { pid, title, author, urls.small: "https://i.pixiv.re/c/540x540_70/img-master/…/107686832_p0_master1200.jpg" }
浏览器  →  GET /api/pixiv/image?url=…（指向上面那张）  ← 本站图片代理 + 磁盘缓存，命中就是毫秒级
           →  未命中时才去社区镜像 pixiv.re 取一次，然后落盘
```

要点：

- 图片地址**直接用接口给的 `urls.small`**（里面含发布日期目录），不用自己猜 CDN 路径；
  手动填作品 id 时用 `https://pixiv.re/{id}.jpg`（多图 `-{页码}`）
- 「在 Pixiv 查看」仍是深链，需要你自己的网络能打开 pixiv.net
- 自检里有六条用例卡住这条链路：服务端代理能取到作品、**连续抽取不重复**、
  **图片代理 + 磁盘缓存命中**、**代理只允许镜像域名**（防开放代理）、数据源注册正确、
  **浏览器真的把图显示出来**

#### 加载速度：从 33 秒降到 0.1 秒

原来的问题：`pixiv.re` 是**按需回源**的镜像，一张 `regular`（1200px，约 600KB-1.3MB）
第一次取要 20-40 秒。做了四件事：

| 做法 | 效果 |
| --- | --- |
| **要小图**：上游 `size=small`（540px） | 同一张图实测 **22.3 秒 / 621KB → 2.4 秒 / 43KB**，十倍 |
| **图片走本站代理 + 磁盘缓存**：`/api/pixiv/image?url=…` | 浏览器只跟 localhost 打交道；命中缓存 **5-8 毫秒** |
| **整池预热**：启动时 + 每次补货后，把池子里的图全取进缓存（并发 4） | 540px 一张三四十 KB，整池 20 张也就几百 KB |
| **常备水位**：`targetWarm = 24`，随时保持 20+ 张「已缓存」可发 | 连点三次以内都是秒开，不用等回源 |
| **不做阻塞探测**（`skipProbe`）+ 服务端「已缓存优先」排序 | 选中就立刻显示，不再先等一轮探测 |

实测（浏览器里连抽 5 次，每次都等图真的渲染出来）：

```
改前：35.2s / 19.0s / 21.5s / 13.3s / 25.4s      平均约 23 秒
改后：60ms / 295ms / 45ms / 141ms / 67ms          平均 122 毫秒
```

冷启动（缓存全清）后约 30-40 秒预热完第一批 20 张；之后就是上面的速度。
缓存目录 `data/.cache/pixiv-img/`（默认最多 600 张，超了按时间删最老的），
大小约 20-30KB/张 —— 想清空直接删目录即可。

> 想换成「只出某个题材」或「不要 AI 图」，改 `server.mjs` 里那行上游地址即可：
> `&tag=風景`（按标签）、`&keyword=…`（按关键词）、`&excludeAI=true`（实测有效，
> 回来的记录 `aiType` 为 1 = 非 AI）。默认 `r18=0`，但请注意公开接口的「非 R18」
> 仍可能包含擦边内容。

#### 为什么一开始会「老是抽到那几张」

第一版把随机结果按 `num` 缓存了 3 分钟 —— 等于同样的 8 张在 3 分钟内反复发出去，
表现就是「怎么老是这几张」。

现在改成**抽卡池**（`server.mjs` 的 `pixivTake` / `refillPixivPool`）：

| 机制 | 说明 |
| --- | --- |
| 一次要一批 | 上游 `num` 上限就是 20（实测 21 直接返回 0 条），一次补满 20 张进池 |
| 逐张发放 | 从池子里按序发，**发过的记进 `served`，同一个作品在进程生命周期内只发一次** |
| 见底补货 | 池子低于 `num * 2` 就后台补货（不阻塞当前请求），所以连点也不会拿到空 |
| 上游限流保护 | 实测连打会被回「请求的太快啦，休息一会吧」并连续返回空，所以有 2.5 秒最小间隔 + 20 秒退避 |
| 客户端再加一道 | 前端把「本次会话已展示的作品 id」用 `&exclude=` 报上来，服务端过滤掉；前端自己也有一份 seen 集合 |

实测（连续 10 次 × 8 张）：

```
80 张 / 去重 80 张 / 重复 0 张 / 失败 0 次
```

浏览器里连抽 5 次也验过：5 个不同 pid、5 张不同图，全部正常渲染。

### 5. 扫雷（`#/mine`）

一个板块级的完整小游戏，规则引擎与视图分开：

```
src/plugins/minesweeper.js   纯逻辑：布雷、洪水展开、插旗、和弦、胜负、战绩
src/views/mine.js            画面与交互：HUD、棋盘、动效、键盘、尺寸自适应
```

**规则细节**

- **第一下必定安全**：雷在第一次点击之后才布置，并且避开点击格及其八邻域
  —— 所以第一下一定会展开一片（边角至少 4 格，中间 9 格起）
- 三档难度：初级 9×9/10 · 中级 16×16/40 · 高级 24×16/75
- **和弦**：点到已挖开的数字，若它周围的旗数正好等于数字，就一次开完周围；
  旗插错了和弦会直接踩雷（和经典规则一致）
- 计时从第一下开始；剩余雷数会随插旗递减（插多了变负）

**交互与反馈**（每步都有回应，不是"点了没反应"）

| 操作 | 反馈 |
| --- | --- |
| 左键挖开 | 展开的格子逐格落下（14ms 级联），HUD 进度条同步 |
| 右键 / 长按 | 插旗：格子变信号黄芯片并弹一下；再点取消 |
| 悬停数字 | 旗数够了 → 预亮将被挖开的格子；没够 → 轻轻晃一下（否定反馈） |
| 踩雷 | 舞台震屏 + 全部雷按顺序翻出（误插的旗被划掉）+ 结算条 |
| 通关 | 整盘按行列扫一道信号色波浪 + 结算条 + 最佳时间 |
| 键盘 | ↑↓←→ 移动光标，空格/回车挖开，F 插旗，R 重开 |
| 触屏 | 长按 500ms 插旗；也可以切到「⚑ 插旗」模式让左键只插旗 |

战绩（已玩 / 胜局 / 胜率 / 最佳时间，按难度分开）存在 `localStorage['ft.terminal.mines']`，
命令面板里也有一条「扫雷：新的一局」。

**对局不会因为切板块而断**（刷新页面也不会）：

- 切板块时视图整个被换掉（router 会换 `#view` 节点），所以对局状态不能放在视图里。
  卸载时把快照交接给模块级变量（会话内最快的一条路），同时写一份进
  `localStorage['ft.terminal.mines.game']`（管刷新）。
- 快照里存的是 `elapsedBefore`（离开时已经用了几秒），读回来时反推 `startedAt`
  —— **相当于离开即暂停**，回来接着走，不会因为在别的板块逛了一圈就被记上几十秒。
- 已结算的局回来**只画结果、不再记一次战绩**（还原路径和 `settle()` 是分开的）。
- 快照会做校验（难度 / 格数 / 雷数对不上就当没有），坏数据宁可开新局，也不还原出一个坏棋盘。

> **三个实现上的坑，都写进了自检**
> 1. `fitCells()` 必须量**舞台的父容器**。舞台是 `width: fit-content`（尺寸由棋盘决定），
>    拿舞台自己当基准会形成循环：越量越小，最后缩到最小格子。
> 2. 棋盘居中用 `margin: 0 auto` 而不是 `justify-content: center` ——
>    后者在内容比容器宽时，会把左侧溢出部分顶到滚不到的地方。
> 3. 「离开即暂停」判断起没起表要用 `startedAt`，**不能**看 `elapsedBefore` 是否非零 ——
>    玩了不到一秒就走它是 0，那样会把离开的时间也算进去。

### 6. 工具台（`#/tools`）

三个工具，**全部在浏览器里跑，文件不上传**：没有后端，所以也不需要把文件交给谁。
内核是 `src/plugins/tools/`（纯函数 + 浏览器 API），界面在 `src/views/tools.js`。

| 工具 | 做什么 | 内核 |
| --- | --- | --- |
| **格式转换** | 图片 / 文档 / 音频互转，可一次拖一批、逐个选目标格式、整包下载 ZIP | `index.js` 调度 |
| **图片压缩** | 批量缩放（最长边）+ 质量 + 换格式，实时看前后体积与合计省下多少 | `image.js` |
| **文本工具** | JSON 格式化/压缩、Base64、URL 编解码、行处理（去重/排序/编号…）、文本统计、文件 SHA-256 | `text.js` |

**支持矩阵**（能做到什么、做不到什么，界面上也写着同一张表）：

| 类型 | 能读 | 能写 |
| --- | --- | --- |
| 图片 | png / jpg / webp / gif(首帧) / bmp | jpg / png / webp（canvas 编码） |
| 文档 | docx（标题、列表、表格都能提出来） | docx（由文本 / Markdown 生成） |
| 文本 | txt / md / html / csv / json | txt / docx |
| 音频 | mp3 / m4a / wav / ogg / flac / webm | **wav**（瞬时）· **m4a / webm**（实时重编码） |

实现上的几个关键决定：

- **docx 双向转换靠自己写的 ZIP 读写**（`zip.js`）。`.docx` 就是一个 ZIP：读的时候解开
  `word/document.xml` 解析 XML；写的时候只用「存储」模式打包 —— 存储模式不需要压缩器，
  正好绕开"浏览器没有同步 deflate"这件事，而 Word / WPS / LibreOffice 照常打开。
  生成时附带一份最小 `word/styles.xml`，标题才会是**真的标题**（Heading 1/2），不只是大号粗体。
- **mp3 → m4a 是"实时重编码"**：浏览器没有离线 AAC 编码器，但 `MediaRecorder` 能录媒体流，
  于是把解码后的音频送进 `MediaStreamAudioDestinationNode` 边播边录 —— 代价是**耗时≈音频时长**。
- **MP3 编码明确不做**：需要第三方编码器（LAME 之类），与本项目的零依赖相冲突。
  与其放一个点了没反应的假按钮，不如在支持矩阵里写清楚。
- **PDF / XLSX / PPTX 也不做**：解析量级远超"顺手写个小工具"。

> 自检里对这套工具是**真跑**，不是检查按钮在不在：造一个 docx 再读回来（标题/列表/表格都要在）、
> canvas 编一张噪声 PNG 转 jpg/webp 并缩放、合成 1.2 秒音频 → WAV → 解码 → 录成 M4A
> 并检查 `ftyp` 头、SHA-256 对一个已知向量（`abc`）。
> 另外用 `python-docx` 独立读过生成的文件：`[Heading 1] / [Normal] / [Heading 2] / [List Paragraph]`
> 与表格都识别正确 —— 说明生成的不是"能下载但打不开"的空壳。

## 扩展指南

站点的所有可变部分都通过 `src/core/registry.js` 暴露，**加功能不需要改核心代码**。
在 `src/main.js` 里注册即可（该文件底部已有可运行的示例）。

### 新增一个页面

```js
import { Registry } from './core/registry.js';

Registry.addRoute({
  id: 'lab',
  title: '实验室',
  render(ctx) { return `<section><h1>LAB ${ctx.params[0] || ''}</h1></section>`; },
  mount(root, ctx) { /* 绑定交互，返回清理函数 */ },
});
// 同时出现在顶栏与命令面板
Registry.addNav({ id: 'lab', path: '#/lab', label: 'LAB', cn: '实验室' });
```

> 路由 id 就是 hash 的第一段，**必须全局唯一**：列表用 `posts`，详情用 `post`，
> 否则 `#/posts/xxx` 会先命中列表视图。

### 新增一个插画数据源

```js
Registry.addImageProvider({
  id: 'custom-source',
  label: '自建图库',
  kind: 'remote',
  endpoint: 'https://api.example.com/random',
  pick: (json) => json.images.map((i) => i.url),   // 返回 URL 数组
});

// 或纯本地：
Registry.addImageProvider({ id: 'local2', label: '离线图库', kind: 'local' });
// 数据来自 data/gallery.json
```

### 新增命令面板命令

```js
Registry.addCommand({
  id: 'export-all',
  label: '导出全部内容为 JSON',
  hint: 'IO',
  run: (ctx) => ctx.exportAll(),
});
```

### 往首页插入组件

```js
Registry.addWidget({
  id: 'hero-banner',
  slot: 'after-hero',        // hero-actions | after-hero | before-footer
  render: () => '<div class="panel">自定义内容</div>',
  mount: (root) => { /* 可选，返回清理函数 */ },
});
```

### 换主题

在 `styles/tokens.css` 里加一个变量块，再登记到 `site.config.js`：

```css
[data-theme="sunset"] {
  --paper: #FFF3E6;
  --ink-100: #2B1B12;
  --signal: #FF7A3C;
  /* 只写需要覆盖的变量，其余沿用默认值 */
}
```

```js
export const THEMES = [
  { id: 'sunset', label: 'SUNSET', hint: '暖色黄昏' },
];
```

顶栏导航的「当前板块」高亮也走同一套变量：`.nav__link.is-active` 用 `--signal` 铺底、
`--signal-ink` 作字色（见 `styles/base.css`），所以换主题时高亮色会自动跟着变，
不需要为每个主题单独写导航样式。

### 改品牌标记 / 图标

顶栏左上角、浏览器页签、开机画面、页脚用的是**同一张品牌插画**（`assets/img/brand/source.jpg`，
一张线稿），由 `tools/make-brand.py` 用项目自带的 Pillow 裁切生成整套尺寸：

| 文件 | 用在哪 | 规格 |
| --- | --- | --- |
| `assets/icons/mark-512.png` | 开机画面 | 512×512 母版（头 + 头发那一块） |
| `assets/icons/mark-64.png` | 顶栏 32px、页脚 22px | 同上，缩小版 |
| `assets/icons/favicon-32.png` | 浏览器页签 | 32×32，**裁得更紧的「脸」** + 墨色留白 2px（16px 下才看得出是张画） |
| `assets/icons/apple-touch-icon.png` | iOS 主屏图标 | 180×180，同一张脸 + 墨色留白 12px |
| `assets/icons/logo.svg` | 字标（文档 / 备用） | 2×2 色块 + `TEMPLE OF FISH` 的方形字标 |

```bash
# 换品牌图：把新图放到 assets/img/brand/source.jpg，然后
python tools/make-brand.py
# 想改裁切（坐标是原图像素，x1,y1,x2,y2）：
python tools/make-brand.py --box 647,47,1407,807 --icon-box 747,200,1307,760
```

顶栏与页脚里的标记是 `<img>`（`index.html` 的 `.brand__glyph` / `.footer__logo`），
外面套着一个**墨色外框**：插画是线稿、不能反色，所以悬停时由外框变信号黄来表态，
和站内「选中即信号黄」的语言一致。`verify.mjs` 里有几条用例卡着它（标记尺寸 /
图片真的加载出来 / 图标 URL 带版本号 / 图标文件可解码）。

> **换图标一定要改 URL**：浏览器对 favicon 的缓存极其顽固（存在独立的 Favicons 库里），
> 换了文件不换地址，页签会一直显示旧图标，硬刷新也不一定管用。所以图标链接都带 `?v=N`
> —— 改完图标把 N 加一，或者让用户到 `chrome://settings/clearBrowserData` 清一次缓存图片。
> 自检里有一条专门断言这些 URL 都带版本号。

> **手写 SVG 的坑**（换插画之前踩过一次）：XML 注释里**不能出现连续两个短横线**（`--`）。
> 写了的话整份文件直接判定为非法，`<img>` 里就是裂图（`<link rel="icon">` 又不会报错，
> 很容易一直没发现）。自检里有一条用例专门用 `DOMParser` 卡这个。

`store.js` 里的 `createCollection()` 是通用的。要加「相册」只需三步：

## 服务器 API（`server.mjs`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 服务状态、内容目录、是否可写（只读部署下 `writable: false`）、`deploy`（`'local'` / `'netlify'`）与 `readonly`、网易云代理是否启用（`netease` 端点里含 `audio`）、pixiv 端点列表（含 `image`） |
| `GET` | `/api/tree` | 项目文件树（控制台展示用） |
| `GET` | `/api/content/:collection` | 读取集合（`posts` / `news` / `gallery`）。**本地**回文件的完整内容（`overlayOnly:false`）；**线上**回"线上发布的覆盖层"（`overlayOnly:true`），由前端按 `id` 合并到静态 `data/*.json` 之上（覆盖层胜出） |
| `POST` | `/api/content/:collection` | 新增或更新（按 `id` 去重合并）。**仅站长**：本地本机免登录（写 `data/`，可 git 提交）；线上必须带站长令牌（写 Blobs） |
| `DELETE` | `/api/content/:collection/:id` | 删除一条（同样仅站长） |
| `GET` | `/api/netease/search?q=关键词&limit=20` | 搜索网易云曲目（元数据）。**按顺序试 5 个搜索入口**，第一个有结果的就用：响应里 `via` 说明命中了哪个入口；只有全都拿不到结果时才回显 `upstreamTried`（每个入口的结果或报错）。见下面的「搜索为什么有 5 个入口」|
| `GET` | `/api/netease/songs?ids=1,2,3` | 批量取曲目详情（封面 / 时长 / 付费标记，单次最多 50 个 id） |
| `GET` | `/api/netease/playlist?id=3778678&limit=300` | 公开歌单：元数据 + 完整曲目 id 列表（导入歌单用） |
| `GET` | `/api/netease/lyric?id=347230` | 歌词 LRC 文本（板块标题栏的跟唱要用） |
| `GET` | `/api/netease/resolve?url=163cn.tv%2Fxxxx` | 展开 `163cn.tv` / `music.163.com` 短链（只允许网易云域名） |
| `GET` | `/api/netease/playable?id=643982` | 匿名态能否播放（`false` = 会员曲目外链不出声），结果缓存 30 分钟。与 `/api/netease/audio` **复用同一个 `resolveNeteaseAudio()`**，保证"判定"与"实际播放"不会分叉 |
| `GET` | `/api/netease/playable?detail=1&id=2041508513` | 从音频本身量出的真实秒数（`seconds`/`bitrate`/`mode`），iframe 回退路径的自动下一首与"试听片段"判定都用它 |
| `GET` | `/api/netease/audio?id=643982` | **音频**：`resolveNeteaseAudio(id)` 按顺序试**两个入口** —— ① `song/media/outer/url`（302 → CDN）② `/api/song/enhance/player/url?ids=[id]&br=128000`，各带独立超时；URL 过网易云 CDN 白名单并升级 https，解析结果缓存 15 分钟。本地是**同源流**（支持 Range/206，`Cache-Control: private, max-age=86400`，**服务端不落盘**）；serverless 部署下改成 **302** 到解析出的 CDN 地址（Range / 拖动 / 后台播放交给 CDN，函数不扛流量）。两种模式都带诊断头 `X-Netease-Audio-Via` / `-Bitrate` / `-Trial`；两处都拿不到流时返回 `404`，响应体里列明每个入口的结果（如 `（outer:no、enhance@128000:code-110）`） |
| `GET` | `/api/netease/status` | 代理状态与各缓存条目数（含 `audioEntries`） |
| `GET` | `/api/auth/config` | 公开：`{ enabled, domain, clientId, audience, ownerConfigured }`。`enabled:false`（没配环境变量）时前端不显示登录入口，账号相关接口回 `501` |
| `GET` | `/api/auth/me` | 校验 `Authorization: Bearer <token>`（也认 `Cookie: ft_token=`）并回当前身份 `{ sub, email, name, picture, verified, role }`（`role` = `owner` / `member`）；顺便把账号资料落一份到 `users/` |
| `GET` | `/api/auth/users` | **仅站长**：列出账号（昵称 / 邮箱 / 角色 / 最近出现 / 访问次数），邮箱只对站长可见；普通账号 `403`、未登录 `401` |
| `GET` | `/api/forum/posts?limit=&offset=&q=` | 论坛列表（公开可读，返回摘要，最新在前） |
| `GET` | `/api/forum/posts/:id` | 论坛帖详情（公开） |
| `GET` | `/api/forum/mine` | 我发的帖（需登录） |
| `POST` | `/api/forum/posts` | 发帖（需登录且邮箱已验证；同账号 15 秒一贴、每天 40 贴） |
| `PATCH` / `DELETE` | `/api/forum/posts/:id` | 改 / 删：**只有作者本人**（站长可代管），否则 `403` |

`/api/content/*` 的**写入**现在不是"只读"而是"**要有身份**"：配好 Auth0 就必须是站长
（未登录 `401`、登录了但不是站长 `403`）；没配 Auth0 时，本机访问仍可写 —— 也就是你原来
"本地控制台写 `data/` + git 提交"的工作流原样保留 —— 线上则回 `501` 并明确告诉你要配哪三个
环境变量。**无论哪种情况都不会假装成功**。详见「账号 / 权限 / 论坛」与「部署」两节。

> 顺带修掉一个真实的老 bug：`/api/pixiv/illust` 原本有**两个一模一样的分支**，
> 而且第一个分支直接把**未代理**的 `pixiv.re` 原链返回并提前 return —— 也就是说那个
> 写好的代理版本（`/api/pixiv/image?url=…`）是死代码，而浏览器根本加载不了 pixiv.re 直链。
> 现在只保留代理分支，这个端点返回的是代理 URL。

网易云代理的三个约束，写在这里以免以后踩坑：

1. **元数据接口只转发元数据**；会碰音频流的只有 `/api/netease/audio`，而且只转发网易云**对匿名访客本来就返回**的那个外链流（302 → CDN）。不登录、不碰 VIP / DRM，**不在磁盘上存任何音频**；拿不到流就回 `404` —— 前端不会就此认输，它会先用**访问者自己的 IP** 再试一次，仍不行才回退官方外链播放器。
2. 内置 5 分钟内存缓存 + 350ms 最小调用间隔，避免触发对方风控。
3. 若被限流会返回明确错误（`网易云返回的不是 JSON（可能被风控）`），前端会提示搜索失败。

> ⚠️ **码率规则：只请求 128000（标准 / 免费档），永远不要请求更高码率。**
> `enhance` 入口确实会执行网易云的权限门槛，实测：
> - 真 VIP 曲目（`fee=1`：Taylor Swift《Love Story》《Cruel Summer》、陈奕迅《富士山下》原版）
>   → 回 `code=-110`，**没有 URL**；
> - 但对 `fee=8` 的曲目，如果把 `br` 提到 `320000`，它会给出 `level=exhigh` 的 320kbps 地址 ——
>   那是**付费档**，本项目不拿。
>
> 所以只发 `br=128000`：免费档拿得到就播，拿不到就诚实回 `404`，让前端走上面那条回退链。
> 另外，**同一个 id 本地家宽 IP 能解析、Netlify（AWS）IP 解析不了，是网易云按 IP 的行为，
> 不是 bug** —— 客户端为此专门有"用访问者自己的 IP 再试一次"这一级（见「为什么 PC 有声音、手机没声音」）。

#### 搜索为什么有 5 个入口（部署到国外机房后暴露出来的）

网易云的搜索接口对**机房 IP** 与家宽 IP 的响应不一样。实测：同一个查询，
本地（国内家宽）返回 301 条，而线上（Netlify Functions 跑在 AWS）返回
`ok: true, total: 0, songs: []` —— 而 `/api/netease/songs`（按 id 取详情）两边都正常，
所以不是"接口挂了"，是这一个入口对那个来源 IP 不给结果。

于是搜索改成依次尝试这 5 个入口（`NETEASE_SEARCH_CANDIDATES`），谁先给出结果就用谁：

| 顺序 | 入口 id | 方法 |
| --- | --- | --- |
| 1 | `search/get/web·GET` | GET |
| 2 | `search/get/web·POST` | POST（表单）|
| 3 | `cloudsearch/pc·POST` | POST（表单）|
| 4 | `search/complex/get·GET` | GET |
| 5 | `search/suggest/web·GET` | GET |

要点：**每个入口单独缓存**（否则一个入口的空结果会污染另一个）；全空时把尝试过程
放进 `upstreamTried` 回显出来 —— 以后哪个入口失效，线上一个请求就能看出来，不用猜。
线上实测命中 `via=cloudsearch/pc·POST`，`total=301`。

- 写入前自动备份到 `data/.backup/`（同一集合最多保留 20 份）
- 采用「写临时文件 + rename」的原子写入，避免中断导致文件损坏
- 只允许读写白名单集合，静态文件服务限制在项目根目录内（拒绝路径穿越）
- 跨域预检（`OPTIONS`）放行 **`Authorization` 请求头**与 **`PATCH` 方法** ——
  论坛改帖与内容写入都要带 Bearer 令牌，少了这两项浏览器会在预检就被拦下

```bash
node server.mjs          # 默认 5173
node server.mjs 8080     # 指定端口
PORT=8080 node server.mjs
```

## 部署

### 搬到自己的服务器（VPS）：完整步骤见 `deploy/README.md`

如果你想让站点跑在**自己的云服务器**上（自己的域名 + HTTPS，不受任何平台额度/暂停影响），
照着 [`deploy/README.md`](deploy/README.md) 敲即可 —— 那份文档覆盖：装 Node、建专用系统用户、
systemd 单元、Caddy 自动 HTTPS、Auth0 追加回调地址、**数据与备份**（`data/` 是唯一真实数据源）、
从 Netlify 迁移的注意事项、更新与回滚、故障排查，以及可选的 Docker 路径。

配套资产都在 `deploy/`：`fish-temple.service`（systemd）、`Caddyfile`（反代 + 自动证书）、
`fish-temple.env.example`（环境变量占位示例）、`Dockerfile` + `docker-compose.yml`、`backup.sh`（定时备份）。

两点最关键的：

- **零依赖**：VPS 上**不需要 `npm install`**。唯一的 npm 依赖 `@netlify/blobs` 只在 Netlify 上被
  **动态引入**，VPS 上根本不会加载它。
- **存储驱动是自动切的**（见 `storage.mjs`）：在 Netlify 上写 **Netlify Blobs**；在 VPS/本机写
  **仓库下的 `data/`**。同一份代码、同一条 `node server.mjs`，不需要你改任何配置去"选择模式"；
  唯一的差别是**数据不互通** —— 线上 Blobs 里已有的论坛帖/账号资料/播放历史**不在仓库里**，
  搬到 VPS 后会以仓库 `data/*.json` 为起点（详见 `deploy/README.md` 的"从 Netlify 搬过来"一节）。

> Netlify 那条通道**保留**（`netlify/` 与 `netlify.toml` 不需要改），两边可以并存做备用；
> 但建议**只对外宣称一个地址**，否则同一个站点会出现两套互不相同的内容（一边 Blobs、一边文件）。

### 纯静态托管：能用，但 `/api/*` 全废

把整个目录（`tools/`、`server.mjs`、`netlify/` 可省略）上传即可，hash 路由不需要任何 rewrite。
适合 GitHub Pages / Cloudflare Pages / 任意对象存储 + CDN。

代价是 `/api/*` 一律 404，于是：音乐台显示 `PROXY OFFLINE`（搜索框禁用）、Pixiv 抽卡与图片代理失败、
黄历的吉日之歌也放不出来。这不是配置没写对，而是**这些上游只能经本站服务器访问**（实测）：

| 上游 | 为什么浏览器直连不行 |
| --- | --- |
| `api.lolicon.app` / `nekos.best` / `waifu.pics` | 不返回 CORS 头 → 浏览器 `fetch` 被同源策略拦掉 |
| `i.pixiv.re`（图片） | 浏览器里 `fetch` 与 `<img>` 都取不到，服务器取得到 → 所以统一走 `/api/pixiv/image` 代理 |
| `music.163.com` | 同样没有 CORS 头，而且音频流要 `Referer` |

### Netlify：连接口一起跑

`netlify.toml` 已经把这件事配好了，从 Git 部署**不需要再填任何东西**：

```toml
[build]
  publish = "."                     # 没有构建命令，直接发布仓库根目录

[functions]
  directory = "netlify/functions"
  node_bundler = "esbuild"
  included_files = ["server.mjs"]   # 万一没走打包，也能解析到那个相对 import

# ⚠️ 这里**故意没有** [[redirects]]：函数用 config.path 自己声明路由，
#    再加 /api/* 重写会把请求转到一个已不存在的地址 → 全 404。详见下面第 1 条。
#    文件里另有 [[headers]]（图标长缓存、/data/* 短缓存），此处省略。
```

`netlify/functions/api.mjs` 是 **Functions v2 形态**：`export default async function api(request)`
直接收 Web `Request`、返回 Web `Response`，路由由 `export const config = { path: '/api/*' }` 声明
（没有 v1 的 `event`/`context` 适配层，也不再往默认地址 `/.netlify/functions/<name>` 上挂）。
它**直接 import 同一个 `server.mjs`**，调用 `handleApiRequest(request, { serverless: true })` ——
也就是说：**本地那 1500 行代理实现一行都没有重写**，Netlify 上跑的就是同一份代码。

为了能被 import，`server.mjs` 做了一次**无行为变化**的拆分：`IS_MAIN` 判定（import 不再启动
HTTP 监听）、HTTP 处理抽成 `handleHttp()`、`server.listen()` 与 SIGINT 收进 `if (IS_MAIN) { … }`，
并新增 `WebResponseSink`（一个把 `writeHead` / `setHeader` / 正文录进 Web `Response` 的 `Writable`）。
本地 `node server.mjs` 的行为和以前完全一样。

**只有三处 serverless 差异**，而且都是显式 opt-in：

| 差异 | 本地 `node server.mjs` | Netlify |
| --- | --- | --- |
| 内容写入 `/api/content/*` | 可写（落盘 `data/`，自动备份到 `data/.backup/`） | 代码已支持在线发布（写 **Netlify Blobs**），但**必须带站长令牌**；没配账号时回 `501` 并提示配哪三个环境变量。前台读取：线上返回"覆盖层"，由前端合并到静态 `data/*.json` 之上 |
| 音频 `/api/netease/audio?id=…` | **同源流**（支持 Range / 206） | **302** 到解析出来的网易云 CDN 地址（`https://m*.music.126.net/...`）：Range / 拖动进度 / 后台播放都由 CDN 原生处理，函数不扛流量 |
| Pixiv 图片缓存 | 磁盘缓存（`data/.cache/pixiv-img/`） | 不写盘（`cachePixivImage(..., { noDisk: true })`，函数目录只读），响应加 `Netlify-CDN-Cache-Control: public, max-age=604800, durable` —— 用 **Netlify 边缘缓存**顶替本地磁盘缓存 |
| 内容存储 | 文件（`data/`，可 git diff / 回滚） | **Netlify Blobs**（跨部署持久，发布不用重新部署）——见 `storage.mjs` 的双驱动 |

`/api/health` 会报 `deploy: 'netlify' | 'local'` 与 `readonly`（只读时 `writable: false`），
pixiv 端点列表里也补上了 `image`；serverless 下还会多一个 `netlifyEvent`
（`{ requestUrl, resolvedPath, resolvedBy }`），用来确认线上给函数的是哪种路径形状。
现在还多了三项：`auth`（`{ enabled, domain, clientId, ownerConfigured }`）、
`storage`（`'fs'` / `'blobs'`）与 `forum`（端点列表）。

#### ⚠️ 1. 函数声明了 `config.path` 之后，不要再加 `/api/*` 重写（最容易误判的一条）

官方文档（docs.netlify.com → Configuration for functions → Routing）写得很明确：
**一旦设了 `config.path`，函数就只在该路径可用，默认地址 `/.netlify/functions/<name>` 不再存在**。
而 `[[redirects]] from = "/api/*" to = "/.netlify/functions/api/:splat"` 正是把请求转发到那个
**已经不存在**的地址 —— 于是每个接口都变成 Netlify 的 `Page not found` 404，看起来就像
"函数根本没部署"。线上就是这么演进的，时间线最能说明问题：

| 阶段 | 函数形态 | `/api/*` 结果 |
| --- | --- | --- |
| 只加了重写 | 没有 `config.path` | ✅ 能通（函数真实的报错都露出来了）|
| 之后加了 `config.path` | 有 `config.path` | ❌ 全部 404 "Page not found" |

现在 `netlify.toml` 里**没有**这条重写。`handleApiRequest` 仍然会把
`/.netlify/functions/api/...` 还原成 `/api/...` 作为兜底（本地仿真用 `NETLIFY_FAKE_FN_PATH=1` 验这条）。

#### ⚠️ 2. 顶层 `__filename` / `__dirname` 会让打包后的函数直接 502

线上 `/api/health` 曾经返回：

```json
502 {"errorType":"SyntaxError","errorMessage":"Identifier '__filename' has already been declared"}
```

原因：Netlify 把 `server.mjs` **当作 CJS 打进函数**，而 Node 的 CJS 包装器本身就有
`__filename` / `__dirname` 两个形参 —— 顶层再写 `const __filename = …` 属于**模块加载期**的
SyntaxError，于是**每一个** `/api/*` 都 502。`server.mjs` 现在改用 `THIS_FILE` / `THIS_DIR`。
本地 `node server.mjs` 是直接跑 ESM 源码的，所以这一类问题**在本机永远复现不出来**。

`tools/verify-deploy.mjs` 为此加了一条**零依赖的静态检查**：扫 `server.mjs` 与
`netlify/functions/api.mjs` 的顶层声明有没有撞 CJS 包装器名
（`__filename` / `__dirname` / `module` / `exports` / `require`），以及有没有顶层 `await`。
**对着远程 URL 也能跑**，而且拿旧写法试过，确实能报出来。

#### ⚠️ 3. 函数必须是 v2 形态，不能又 `export default` 又返回 v1 的对象

曾经同时存在 `export default` 与 v1 的 `{ statusCode, headers, body }` 返回值，Netlify 按 v2 调用，于是：

```json
502 {"errorType":"NetlifyUserError","errorMessage":"Function returned an unsupported value. Accepted types are 'Response' or …"}
```

现在只保留 v2（收 `Request`、返回 `Response`），不再有 event 形状的歧义。

#### 部署踩坑清单（现象 → 原因 → 处理）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 所有 `/api/*` **502**，`Identifier '__filename' has already been declared` | 顶层 `__filename` / `__dirname` 与 CJS 包装器形参撞名 | 改名成 `THIS_FILE` / `THIS_DIR`；`verify-deploy` 的静态 lint 会提前拦住 |
| 所有 `/api/*` **404** `Page not found`，但静态文件正常 | 函数声明了 `config.path`，同时又加了 `/api/*` 重写 → 转发到已不存在的默认地址 | 删掉那条 `[[redirects]]`（**别补回来**）|
| `/api/*` **502** `Function returned an unsupported value` | 混用 v1 返回值与 v2 调用 | 只保留 v2：`export default` 返回 `Response` |
| 音乐台连得上、但搜索永远 0 条（`total: 0`），按 id 取详情却正常 | 网易云搜索接口对**机房 IP**（Netlify Functions 在 AWS）与家宽 IP 响应不同 | 已内置 5 个搜索入口依次回退；看响应里的 `via` 判断命中了哪个 |
| 整个站点（含 `/api/*`）**401** + `Login Redirect` HTML | Netlify 的访问保护（Edge Access / 密码 / visitor access） | 后台 Site configuration → Access & security 关掉，或改成只保护首页、排除 `/api/*` |
| 线上响应里没有 `netlify-cdn-cache-control` | 该头在 Netlify 边缘被消费掉，不会回给客户端（边缘缓存仍然生效）| 正常现象；本地仿真会把它回显出来 |
| 搜索接口偶发 `503 上游正在限流` | api.lolicon.app 限流 | 站点如实上报；`verify-deploy` 会等 15 秒重试一次，仍失败记为 SKIP |

#### ⚠️ 不要加 SPA 兜底重定向

**不要**加 `/* → /index.html 200` 这种 catch-all。本站是 hash 路由，根本不需要它；
而它会把 `data/album.json`、`assets/img/album/*.jpg` 一并重写成 `index.html`，
于是相册清单解析失败、每张相册图都显示不出来 —— 也就是说，**它会亲手制造"随机相册不能用"**。
线上相册出问题时，第一个要检查的就是有没有这条规则。

#### 反过来：只传静态文件同样不行

用拖拽上传或 CLI 时要留意：Functions 目录必须一起上传 / 打包（CLI 会自动做）。
只做纯静态上传 = 退化成上面「纯静态托管」，Pixiv / 音乐台 / 吉日之歌全部不工作。
线上 `/api/health` 返回 **404** 时，先怀疑这一条；但如果返回的是 **401 + Login Redirect**，
那是平台级的访问保护（见上面的踩坑清单），两条要分清。

> **唯一还没做的是"真实 Auth0 登录"的线上验证** —— 那需要在 Netlify 配好下面那三个环境变量，

### 谁能做什么

| 角色 | 论坛发帖 / 改自己的帖 | 改别人的帖 | 改公告与网站现有文案 | 看账号列表 |
| --- | --- | --- | --- | --- |
| 游客（未登录） | ❌ `401` | ❌ | ❌ `401` | ❌ `401` |
| 登录用户（member） | ✅（需邮箱已验证） | ❌ `403` | ❌ `403` | ❌ `403` |
| 站长（owner） | ✅ | ✅（可代管） | ✅ | ✅ |

角色只有一个判据：令牌里的邮箱在 `OWNER_EMAILS` 白名单里，**并且** `email_verified === true`。

### 为什么用 Auth0（而不是自己存密码）

- **Netlify Identity 已弃用**，Netlify 把账号需求引向 Auth0 这类外部服务，所以这里用 Auth0。
- 浏览器走 **Universal Login + PKCE**：密码只在 Auth0 的页面上输入，**从不经过我们的代码**；
  邮箱验证邮件与「忘记密码」也由 Auth0 负责 —— 这两件事自建账号体系做不到。
- 服务端只干两件事：验签（`auth.mjs`：RS256 + JWKS，只用 `node:crypto`，无第三方库）与判角色。
- ⚠️ **站长判定要求 `email_verified === true`**：否则任何人都能用站长邮箱注册一个未验证账号来冒充站长。

### Auth0 配置清单

1. Auth0 后台 → **Applications → Create Application**，类型选 **Single Page Application**（我们是浏览器端 PKCE）。
2. 在该应用的 **Settings** 里填：
   - **Allowed Callback URLs**：`https://yumiao.netlify.app/`（本机调试再加 `http://localhost:5173/`、`http://127.0.0.1:5173/`）
   - **Allowed Logout URLs**：同上
   - **Allowed Web Origins**：`https://yumiao.netlify.app`（本机再加 `http://localhost:5173`）
3. 复制 **Domain**（形如 `dev-xxxx.us.auth0.com`）与 **Client ID**。
4. Netlify → **Site configuration → Environment variables** 新增三条：

   | 变量 | 值 | 说明 |
   | --- | --- | --- |
   | `AUTH0_DOMAIN` | `dev-xxxx.us.auth0.com` | **只填域名**，不要带 `https://` |
   | `AUTH0_CLIENT_ID` | 你的 Client ID | |
   | `OWNER_EMAILS` | `qiyuyu197@gmail.com` | 站长白名单，逗号或空格分隔，可写多个 |

   （可选 `AUTH0_AUDIENCE`：只有建了 Auth0 API 才填；本实现用 ID Token 校验，留空即可。）
5. 注册之后去邮箱点验证链接 —— **验证通过**才会被认成站长（这是我特意加的安全边界，不是 bug）。

没配这三条时整套账号功能**优雅降级**：`/api/auth/config` 报 `enabled:false`、账号相关接口回 `501`、
前端不显示登录入口；线上的内容写入也回 `501` 并提示去配这三个变量 —— **不会假装成功**。

### 存储：本地写文件，线上写 Netlify Blobs

`storage.mjs` 把两种后端藏在一个接口后面：

| 形态 | 写在哪 | 为什么 |
| --- | --- | --- |
| 本地 `node server.mjs` | `data/`（`posts.json` / `news.json` / `gallery.json` / `forum/*.json` / `users/*.json`） | 写完就是一条 git diff：能 review、能回滚 |
| 线上（Netlify Functions） | **Netlify Blobs**（跨部署持久） | 部署产物是只读的，但 Blobs 能写；发布内容**不用重新部署** |

- `@netlify/blobs` 是**唯一**的 npm 依赖，而且**只在线上动态引入**（本地开发不需要装）；
  站点本身仍然是零依赖的静态站。
- 线上读取走**覆盖层**：`GET /api/content/:collection` 回 `{ items, storage:'blobs', overlayOnly:true, deleted:[…] }`，
  由前端按 `id` 合并到静态 `data/*.json` **之上**（覆盖层胜出），**再按 `deleted` 里的 id 剔除**。
  函数里读不到仓库那份 `data/*.json`（被打包产物排除在外），所以合并放在前端 ——
  这样「网站现有文案」不会因为上线而消失。
- **墓碑（`deleted`）**：线上删除一条内容时，只把它从覆盖层里拿掉是不够的 —— 那等于"从没发布过"，
  前端一合并，仓库 seed 里那条又冒出来（表现为**线上删掉的公告刷新后又出现**）。
  所以线上删除会留下 `{ id, __deleted: true, deletedAt }` 这条墓碑，`GET` 通过 `deleted` 告诉前端剔除它；
  重新发布同一 id 会撤销墓碑；**只在仓库 seed 里、覆盖层没写过的 id 也允许删**（函数读不到 seed，
  没法验证它是否存在，而前端只会删它显示过的东西）。本地（文件即真相）不写墓碑，`deleted` 恒为空。
- 本地仿真：`tools/netlify-dev.mjs` 注入一个 **Blobs 替身**（目录即 store，写在 `.blobs-dev/`，已 gitignore），
  于是「线上发布 → 写覆盖层 → 读到覆盖层」这条链路在没有 Netlify 凭据时也能被真实验证。
- 账号资料也落库：`users/<sha1(sub) 前 32 位>.json`，记 `sub / email / name / role / verified /
  firstSeenAt / lastSeenAt / visits`。键要哈希是因为 Auth0 的 `sub` 形如 `auth0|6ac9…`（含 `|`），
  不能直接当文件路径或 Blob 键。

### 论坛接口

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| `GET` | `/api/forum/posts?limit=&offset=&q=` | 公开（摘要、最新在前） |
| `GET` | `/api/forum/posts/:id` | 公开（全文） |
| `GET` | `/api/forum/mine` | 需登录 |
| `POST` | `/api/forum/posts` | 需登录且邮箱已验证；限流：同账号 15 秒一贴、每天 40 贴 |
| `PATCH` / `DELETE` | `/api/forum/posts/:id` | **只有作者本人**（站长可代管） |

- 帖子字段：`{ id, title, body, tags, author: { sub, name, role }, createdAt, updatedAt, edited }`；
  作者邮箱只存服务端，公开接口不会带出去。
- 限制：标题 ≤120 字、正文 ≤200000 字、标签 ≤6 个 × 24 字。
- **列表走索引**：Netlify Blobs 一次只能读一个键，若列表靠"列目录 + 逐条读"，一个请求就要读最多 300 个键
  （慢，而且很快吃掉读配额）。所以服务端另外维护一份轻量索引（标题 / 标签 / 作者 / 时间 / 摘要，
  存在 `forum-index` 集合里），`GET /api/forum/posts` 只读它一个文档。索引是**派生数据**：
  写失败只记日志、不影响发帖本身；索引丢失（例如内容由旧版本写入）时列表会**按需重建**并落库。
  编辑一篇旧帖**不会**让它跳到列表顶部 —— 顺序始终按创建时间倒序。
- 论坛与「文章与公告」（`#/logs`）是**两个东西**：后者是站长的公告与文章，只有站长能改；
  论坛放用户创作，作者能改自己的、改不了别人的。
- 跨域预检放行了 `Authorization` 与 `PATCH`（见「服务器 API」末尾），否则浏览器在预检就会被拦下。

### 这一块怎么验（`tools/verify-auth.mjs`，53 项）

Auth0 的真实登录要真人点（要跳转、要收验证邮件），没法在自检里点；但**真正危险的部分**
—— 令牌校验与权限判定 —— 完全可以在本地真验。这个脚本起一个**本地模拟 IdP**
（自己生成 RSA 密钥、按标准暴露 `/.well-known/jwks.json`、用私钥真签 RS256 令牌），
让 `server.mjs` 走**完全相同**的校验代码路径：

- 伪造签名 / 过期 / 受众不对 / `alg=none` → 全部 `401`；
- **用站长邮箱但 `email_verified=false` → 只能是普通成员**（防冒充）；
- 普通用户：能发帖、能改自己的帖；改 / 删别人的帖 → `403`；
- 站长：能改公告文案、能代管别人的帖、能看账号列表；普通用户看账号列表 → `403`、未登录 → `401`；
- 空标题 / 空正文 → `400`；同账号连发 → `429`；未登录发帖 → `401`；
  未登录改文案 → `401`、普通用户改文案 → `403`；
- 账号资料确实落库（键是哈希、角色没串）；
- 再用仿真器跑一遍**部署形态**：`deploy=netlify` / `storage=blobs`，站长在线发布 → `200` 且
  `storage:"blobs"`（不再是 `501`），内容确实落到 `.blobs-dev/collections/news.json`，
  公开读取拿到 `overlayOnly:true`，普通用户仍 `403`，论坛帖也写进 Blobs 且别人改不了。

整个过程把内容写进临时目录（`FT_DATA_DIR`），**绝不碰仓库里的 `data/`** —— 跑完 `git status` 应该是干净的。

有几件事**看起来像失败、其实不是**，别把数字读歪：

| 现象 | 说明 |
| --- | --- |
| 线上响应里没有 `netlify-cdn-cache-control` | 这个头在 Netlify 边缘就被消费掉了，不会回给客户端（边缘缓存照样生效）。工具接受"本地仿真回显该头"或"线上响应带 `server: Netlify`" |
| Pixiv 图片偶尔取不到 | `i.pixiv.re` 会限流，也可能某张图上游已经没了。工具**最多换 3 张图重试**，全失败才判失败 |
| 搜到歌了但"没声音" | 很多曲目匿名态本来就没有音频（会员 / 无版权 / 地区）。站点会提示并给替代版本；工具**最多试 4 首**，任一能放即通过；一首都不行时，只有"每首都回 4xx + JSON 说明"才算上游策略，记为 SKIP |
| 整个站点 401 + `Login Redirect` | 是 Netlify 的访问保护，不是代码问题（工具会明说，并给出后台路径）|
| 搜索接口回 `503 上游正在限流` | api.lolicon.app 限流，站点如实上报。工具等 15 秒重试一次，仍失败记为 SKIP |
| **同时跑多个浏览器套件时偶发失败** | 几个 CDP 套件一起开会抢资源，时序敏感的检查就会抖（搜索超时、`Stage.busy`、播放窗口太短）。**一次只跑一个**，别并行 |

修改核心代码或 CSS 后建议都跑一遍 —— 但**一次只跑一个**：这些都是真浏览器套件，
并行会互相抢资源，时序类断言（搜索超时、`Stage.busy`、播放窗口）会无端变红。

## 无障碍与体验细节

- 全站尊重 `prefers-reduced-motion`，控制台内也可一键「关闭动效」
- 焦点可见环、`aria-label`、`aria-live` 提示、语义化标题层级
- 键盘可达：导航、命令面板（`/` 或 `Ctrl/⌘+K`）、播放器、灯箱
- 打印样式：文章页可直接打印 / 存 PDF（自动隐藏导航与侧栏）
- 三种主题 + 两种信息密度，选择会持久化
- **移动端适配层**（`styles/mobile.css`，在 `components.css` 之后加载）：
  - 安全区适配（`env(safe-area-inset-*)`）：刘海屏与底部手势条不压内容
  - 360–430px 手机断点；可点元素的触控目标 ≥ 44px
  - 只在悬停时出现的控件，在触屏上也能点到（不再依赖 hover）
  - 高度用 `dvh` 而不是 `100vh`：移动端地址栏收放不再让版面跳动
  - 宽表格可横向滚动；横屏矮视口有专门修正
  - 黄历面板：触屏关闭键 40px，≤ 620px 左右贴边；顶栏第 4 个图标在触屏上 44px
