## 一个输入框，三种意图

音乐台顶部只有一个输入框。它自己判断要做什么：

| 输入 | 行为 |
| --- | --- |
| 关键词（`夜航星` / `Beyond`） | 搜索曲目 |
| 歌曲链接或纯数字 ID | 直接播放（查不到就再当歌单试一次） |
| 歌单链接（含 `163cn.tv` 短链） | 导入歌单，单次上限 300 首，按曲目 id 去重 |

搜索、导入、粘贴链接原本是三个并排的输入框，谁也不知道该往哪个里粘。合并之后结果区紧贴搜索框下方，**点整行就能播**。

## 播放：官方外链播放器

播放不是在站内解音频，而是嵌入网易云官方播放器 iframe —— 版权与登录由网易云处理。它的参数**只有四个**：

```
type=2        单曲
id=<歌曲 ID>
auto=0|1      0 不自动播放，1 自动播放
height=106    高度
```

它没有 `startTime`、没有 seek、没有音量接口，跨域 `contentWindow` 也读不到。这带来一个必须写在明面上的限制：

> [!WARN]
> **暂停会回到 0:00**。想暂停只能把 iframe 重新加载成 `auto=0`，而重新加载必然从头开始；
> 官方又没给定位参数。所以在官方嵌入方案下，"暂停续播"技术上做不到——界面上也不假装能做到。

唯一的好消息是**切板块不会断**：iframe 只创建一次、永久挂在 `#view` 之外，进入音乐台时把它对齐到页内槽位，离开时改成右下角折叠条。整个过程只改 CSS 定位，不移动也不重建 DOM，所以浏览上下文保留、播放不中断。

## 歌词：官方读不到进度，就自己算

官方 iframe 不给进度，所以站内建了一个**估算时钟**：以起播时刻为基准，加一个校准偏移，每 250ms 走一次。

- 开头 3 秒内带时间戳的「作词 / 作曲 / 编曲」会被过滤掉（那是制作信息，不是歌词）
- 换句有翻转动效：旧句 `rotateX(62deg)` 翻出去 170ms，新句从下转进来 260ms
- 时钟只是估算，所以给了三条纠偏手段：`−0.5s / +0.5s` 微调、点歌词任意一行跳到那句、完整歌词浮层
- 在官方播放器里手动拖进度会让歌词失同步——这一点在说明里讲清楚了，不装作没有

## 会员曲目：明确提示，而不是假播放

VIP / 付费专辑曲目在匿名态下官方外链**不出声**，但播放器条照转、歌词照走，很容易被误认为"正常播放"。服务端可以匿名判定：

```
GET /song/media/outer/url?id=<id>.mp3   （不跟随跳转）
  免费曲目 → 302 到音频路径     能放
  VIP 曲目 → 302 到 /404        放不出来
```

于是站内会：搜索结果里标 `VIP`、给一个「只看能播的」过滤、播到会员曲目时弹出说明块，并**自动找同名的可播放版本**（一键切换）。真的登录了会员的用户，可以点「我登录了会员，能听到声音」把提示收起来。

边界写清楚：不做账号登录，也不搬运音频流。理由见 CONSOLE 里那篇《为什么不做登录》。
