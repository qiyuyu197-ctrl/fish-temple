## 一个输入框，四种输入

音乐台顶部只有一个输入框。它自己判断要做什么：

| 输入 | 行为 |
| --- | --- |
| 关键词（`夜航星` / `Beyond`） | 搜索曲目 |
| 歌曲链接或纯数字 ID | 直接播放（查不到就再当歌单试一次） |
| 歌单链接（含 `163cn.tv` 短链） | 导入歌单，单次上限 300 首，按曲目 id 去重 |
| 专辑链接 | 导入整张专辑，同样按 id 去重 |

搜索、导入、粘贴链接原本是三个并排的输入框，谁也不知道该往哪个里粘。合并之后结果区紧贴搜索框下方，**点整行就能播**；导入歌单或专辑也不会打断正在播放的那一首。

## 播放：先站内直放，失败再回退

默认路径不是在页面里嵌一个第三方播放器，而是经本站同源接口取音频：

```
GET /api/netease/audio?id=<id>
  → 服务端向网易云请求匿名访客本来就拿得到的 128k 外链
  → 同源转发，支持 Range / 206
  → 页面自己的 <audio> 播放
```

所以 `duration`、`currentTime`、`ended` 都是真的：一首完整播完才切下一首，后台标签页和手机息屏也照常。服务端只缓存“外链 → CDN 地址”的解析结果 15 分钟，不把音频写进任何存储。

直放拿不到流时依次回退：访问者自己的 IP 直取官方外链 → 官方外链播放器 iframe。官方 iframe 只接受 `type / id / auto / height` 四个参数，没有进度、没有 seek、没有音量接口，暂停会回到 0:00。这个限制只影响回退路径，页面上会写明，不假装能做到。

## 歌词：官方读不到进度，就自己算

官方 iframe 不给进度，所以站内建了一个**估算时钟**：以起播时刻为基准，加一个校准偏移，每 250ms 走一次。

- 开头 3 秒内带时间戳的「作词 / 作曲 / 编曲」会被过滤掉（那是制作信息，不是歌词）
- 换句有翻转动效：旧句翻出去，新句从下转进来
- 时钟只是估算，所以给了三条纠偏手段：`−0.5s / +0.5s` 微调、点歌词任意一行跳到那句、完整歌词浮层
- 直放曲目改用真实 `currentTime`，歌词和进度条是同一套时钟

## 网易云登录：网页版仅站长，其他人请用 App

音乐台里有一条网易云账号状态带。网页版目前只允许站长绑定自己的账号；其他用户请在 App 版里登录（App 的会话存在自己的设备上，互不影响）。站长扫码绑定后，服务端持有 cookie，前端只拿昵称、头像、歌单和曲目这些能显示的东西，**永远看不到凭据**。

这样限制的原因是：网页端所有用户共用同一个设备指纹，多人同时登录容易触发网易云风控；App 版每台设备各自登录，风险不会串到一起。

站长绑定之后能读：

- 自己的歌单与收藏
- 云盘里自己上传的音频
- 每日推荐

会员曲目默认仍交给官方播放器。想尝试登录态播放，需要自己打开「用这个账号播放会员曲目」开关——它经本站转发，可能触发网易云风控，拿不到流会自动回退官方播放器。开关随时能关，退出登录会清掉服务端会话。

## 会员曲目：明确提示，而不是假播放

VIP / 付费专辑曲目在匿名态下官方外链不出声，但播放器条照转、歌词照走，很容易被误认为“正常播放”。服务端可以匿名判定：

```
GET /song/media/outer/url?id=<id>.mp3   （不跟随跳转）
  免费曲目 → 302 到音频路径     能放
  VIP 曲目 → 302 到 /404        放不出来
```

于是站内会：搜索结果里标 `VIP`、给一个「只看能播的」过滤、播到会员曲目时弹出说明块，并**自动找同名的可播放版本**（一键切换）。

## 播放历史

在本站真正出声之后才记一条 `{ id, title, artist, seconds, at, plays }`。它存在当前浏览器里；登录本站账号后，也会在账号下存一份，换设备能接着听。记录不发给网易云，「在网易云打开」只是一个普通跳转。

## 边界

- 不做 DRM 规避，不逆向需要登录态的加密接口。
- 不把网易云密码交给本站；扫码与登录都由官方页面完成。
- 会员曲目的登录态播放是**用户自愿开启的实验能力**，不是承诺。
- 音频流不落站内存储，只做同源转发。
